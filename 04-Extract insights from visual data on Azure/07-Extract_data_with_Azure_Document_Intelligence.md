# Извлечение данных с помощью сервиса Azure Document Intelligence.

# Введение.

В каждой отрасли, каждый день используются формы и документы для передачи информации. Многие организации до сих пор вручную извлекают данные из форм для обмена информацией, будь то оформление заявок, регистрация пациентов, обработка квитанций для отчетов о расходах или анализ оперативных данных.

Представьте, что вы работаете в компании, которая ежемесячно обрабатывает тысячи счетов, квитанций и налоговых форм. Вы хотите автоматизировать извлечение ключевых данных из этих документов, чтобы сократить ручной труд и повысить точность. Azure Document Intelligence предоставляет инструменты на основе искусственного интеллекта, необходимые для создания подобного решения.

Azure Document Intelligence – это облачный сервис, разработанный в Microsoft Foundry, который использует оптическое распознавание символов (OCR) и модели глубокого обучения для извлечения текста, пар "ключ-значение", таблиц и структурированных данных из форм и документов. Он предлагает готовые модели для распространенных типов документов, модели анализа документов для общего извлечения текста, а также возможность обучать собственные модели, адаптированные к вашим конкретным формам.

# Что такое Azure Document Intelligence?

**Azure Document Intelligence** – это облачный сервис искусственного интеллекта, разработанный в Microsoft Foundry, который использует технологии оптического распознавания символов (OCR) и модели глубокого обучения для извлечения текста, пар "ключ-значение", меток выбора и таблиц из документов.

Технология оптического распознавания символов (OCR) определяет структуру документа, создавая прямоугольные области вокруг обнаруженных объектов на изображении. Координаты этих областей фиксируются относительно остальной части страницы. Сервис Azure Document Intelligence возвращает данные о границах этих областей и другую информацию в структурированном формате JSON, сохраняя связи между элементами, присутствовавшими в исходном документе.

![Скриншот, демонстрирующий работу функции "Интеллектуальная обработка документов", которая анализирует образец документа, извлекая данные и выделяя области с информацией.](https://learn.microsoft.com/en-us/training/wwl-data-ai/extract-data-with-document-intelligence/media/document-intelligence-example.png)

Для создания высокоточной модели извлечения данных с нуля требуются глубокие знания в области машинного обучения, значительные вычислительные ресурсы и длительное время обучения. Azure Document Intelligence предоставляет предварительно обученные модели, которые были протестированы на тысячах образцов документов, поэтому вы можете добиться высокой точности извлечения данных, приложив минимальные усилия.

## Компоненты сервиса распознавания документов.

Azure Document Intelligence включает в себя три категории моделей:

- **Модели анализа документов:** Эти модели извлекают текст, структуру, таблицы и выделенные фрагменты из документов. Модель **"read" (чтение)** извлекает текст и определяет языки, а модель **"layout" (структура)** добавляет функции извлечения таблиц и структуры документа. Вы подробно изучите эти модели в разделе *Использование готовых моделей*.
- **Готовые модели:** Извлекайте информацию из распространенных типов документов, таких как счета-фактуры, чеки, налоговые формы, документы, удостоверяющие личность, и другие, без необходимости проведения обучения. Полный список доступных готовых моделей вы найдете в разделе "Использование готовых моделей".
- **Индивидуальные модели:** Извлекайте данные из форм, специфичных для вашего бизнеса, используя собственные размеченные наборы данных. Доступны следующие варианты: индивидуальные шаблоные модели (быстрые и экономичные для форм с фиксированной структурой), индивидуальные нейронные модели (обеспечивающие более высокую точность для форм с переменной структурой), составные модели и индивидуальные классификаторы. Вы узнаете о том, как обучать и использовать индивидуальные модели, в разделе "Обучение и использование индивидуальных моделей".

## Получите доступ к сервисам интеллектуальной обработки документов.

Вы можете получить доступ к сервису Azure Document Intelligence несколькими способами:

- **REST API:** Обращайтесь к сервису напрямую, используя HTTP-запросы.
- **SDK для клиентских библиотек:** Используйте SDK для языков программирования Python, C#, Java и JavaScript.
- **Document Intelligence Studio:** Онлайн-инструмент для визуального изучения, тестирования и разработки решений в области обработки документов с использованием технологий искусственного интеллекта.
- **Портал Microsoft Foundry:** Интегрируйте технологию распознавания документов (Document Intelligence) с другими инструментами платформы Foundry.

Совет.

Данное упражнение в рамках модуля посвящено работе с библиотекой Python SDK. При этом стоит отметить, что базовые сервисы, работающие по протоколу REST, могут быть использованы из любого языка программирования.

## Создайте ресурс "Интеллект документов".

Для использования сервиса Azure Document Intelligence вам потребуется ресурс в облаке Azure. Вы можете использовать один из следующих вариантов:

- Ресурс Foundry: Подписка, предоставляющая доступ к различным сервисам искусственного интеллекта через единую точку доступа и один ключ.
- Ресурс Azure Document Intelligence: это отдельный ресурс, предназначенный исключительно для использования с сервисом Document Intelligence.

Примечание.

Если вы планируете использовать несколько инструментов Foundry через один и тот же конечный пункт доступа и ключ, создайте ресурс Foundry. Если вам нужен доступ только к сервису Document Intelligence, создайте отдельный ресурс специально для этого сервиса.

## Требования к входным данным.

Сервис Azure Document Intelligence работает с документами, которые соответствуют следующим требованиям:

- Формат файла должен быть JPEG, PNG, BMP, PDF (текстовый или отсканированный документ) или TIFF. Модуль чтения также поддерживает форматы файлов Microsoft Office.
- Размер файла не должен превышать 500 МБ для стандартного тарифа и 4 МБ для бесплатного тарифа.
- Размеры изображения должны быть в диапазоне от 50x50 пикселей до 10 000x10 000 пикселей.
- Файлы PDF должны иметь размеры менее 17 на 17 дюймов (что соответствует формату бумаги A3).
- Файлы PDF не должны быть защищены паролем.

# Используйте готовые модели.

Встроенные модели в сервисе Azure Document Intelligence позволяют извлекать данные из распространенных типов документов без необходимости обучения собственных моделей. Компания Microsoft обучает эти модели на большом количестве образцов документов, поэтому вы можете рассчитывать на точные и надежные результаты при работе со стандартными типами документов.

## Модели анализа документов.

Прежде чем рассматривать готовые модели, предназначенные для конкретных областей применения, важно понять принципы работы моделей анализа документов, на которых они основаны.

### Режим чтения.

Модель распознавания текста извлекает печатный и рукописный текст из документов и изображений. Она определяет язык каждой текстовой строки и классифицирует, является ли текст напечатанным или написанным от руки. Модель распознавания текста используется в качестве основы для извлечения текста во всех остальных моделях интеллектуальной обработки документов.

Для многостраничных файлов в формате PDF или TIFF вы можете использовать... `pages` В вашем запросе необходимо указать диапазон страниц для анализа с помощью соответствующего параметра.

Модель "чтения" идеально подходит для извлечения слов и строк из документов, которые не имеют фиксированной или предсказуемой структуры.

![Скриншот, демонстрирующий работу модели анализа текста в среде Document Intelligence Studio, при обработке образца документа.](https://learn.microsoft.com/en-us/training/wwl-data-ai/extract-data-with-document-intelligence/media/read-prebuilt-sample.png)

### Модель компоновки.
Или: Макет.
Или: Структура расположения элементов.
(Выбор наиболее подходящего варианта зависит от контекста.)

Модель распознавания макета расширяет возможности модели чтения, добавляя функции обнаружения выделений, таблиц и информации о структуре документа. Кроме того, она поддерживает опциональную... `keyValuePairs` Функция для извлечения пар "ключ-значение".

При оцифровке документа он может быть расположен под углом, или таблицы могут иметь сложную структуру с объединенными ячейками или неполными строками. Модель распознавания макета способна справиться с такими сложностями. Каждая ячейка таблицы извлекается вместе со своим содержимым, координатами ограничивающего прямоугольника и индексами строки/столбца.

Отметки выбора (флажки и радиокнопки) извлекаются вместе с информацией об их границах, уровне достоверности и о том, выбраны они или нет.

## Особенности готовых моделей.

Заранее подготовленные модели предназначены для извлечения различных типов данных из документов. К таким возможностям относятся:

- **Извлечение текста:** Все готовые модели извлекают строки и слова из рукописного и печатного текста.
- **Пары "ключ-значение":**  Отдельные фрагменты текста, которые обозначают метку и соответствующее ей значение. Например: **Вес** и **31 кг**.
- **Элементы выбора:** Флажки и радиокнопки, включая информацию о том, выбраны они или нет.
- **Таблицы:** Данные, представленные в ячейках, включая количество столбцов и строк, заголовки столбцов и строк, а также объединенные ячейки.
- **Поля:** Модели, обученные для распознавания конкретного типа документов, идентифицируют фиксированный набор полей. Например, модель для обработки счетов-фактур извлекает... `CustomerName` и `InvoiceTotal`.

## Когда следует использовать готовые модели, а когда – разрабатывать собственные?

Предопределенные модели охватывают наиболее распространенные типы документов. Если у вас есть документы, специфичные для определенной отрасли или уникальные формы, вы можете получить более точные результаты с помощью индивидуальной модели. Однако для обучения индивидуальных моделей требуется время и примеры данных. Прежде чем инвестировать в разработку индивидуальной модели, всегда проверяйте, существует ли готовая модель, подходящая для вашего случая.

# Обучайте и используйте собственные модели.

Если готовые модели не охватывают конкретные типы ваших документов, вы можете обучить собственные модели для извлечения данных из ваших форм. Сервис Azure Document Intelligence поддерживает машинное обучение с учителем: вы помечаете примеры документов, указывая поля, которые хотите извлекать, а сервис обучается распознавать эти поля в новых документах.

## Пользовательские типы моделей.

Сервис Azure Document Intelligence предлагает два типа пользовательских моделей извлечения данных, а также модель классификации.

### Индивидуальные шаблоны моделей.

Модели с использованием пользовательских шаблонов основаны на едином визуальном шаблоне для извлечения размеченных данных. Они наиболее эффективны для структурированных форм, в которых макет остается неизменным от одного документа к другому, например, для анкет, заявлений или стандартных государственных бланков.

Шаблонные модели позволяют точно извлекать размеченные пары "ключ-значение", выделенные фрагменты текста, таблицы, области и подписи. Обучение занимает всего несколько минут, а поддерживается более 100 языков. Благодаря быстрой скорости обучения и экономичности использования, шаблонные модели являются хорошей отправной точкой, когда ваши документы имеют единообразную визуальную структуру.

### Индивидуальные нейронные модели.
Или:
Пользовательские нейронные модели.
Или:
Модели нейронных сетей, разработанные по индивидуальному заказу.
(The best option depends on the context.)

Специализированные нейронные модели используют глубокое обучение и настраиваются на основе ваших размеченных данных. Они объединяют характеристики расположения элементов и языка для извлечения информации из структурированных, полуструктурированных и неструктурированных документов. Нейронные модели поддерживают:

- Перекрывающиеся области.
Или: Области пересечения.
Или: Смежные области.
(Выбор зависит от контекста)
- Обнаружение подписей.
Или: Распознавание подписей.
(В зависимости от контекста)
- Уровень достоверности для таблицы, строки и ячейки.

Нейронные модели обеспечивают более высокую точность по сравнению с моделями, основанными на шаблонах, особенно при работе с полуструктурированными или неструктурированными документами, где структура может различаться в разных случаях. Однако, для обучения нейронных моделей требуется больше времени и ресурсов.

### Выберите между шаблонами и нейронными моделями.

При выборе подходящего типа пользовательской модели необходимо учитывать компромиссы:

| Фактор | Пользовательский шаблон | Пользовательская нейронная сеть |
| --- | --- | --- |
| **Подходит для:** | Структурированных форм с единообразным визуальным оформлением | Полуструктурированных или неструктурированных документов с различной компоновкой |
| **Время обучения** | Минуты | Длительнее (зависит от размера набора данных) |
| **Стоимость обучения** | Ниже | Выше |
| **Точность** | Высокая для форм с фиксированным форматированием; снижается при изменении форматирования. | В целом выше, особенно для документов с различным форматированием. |
| **Поддержка языков** | Более 100 языков | Меньшее количество языков (уточните) | [documentation](/en-us/azure/ai-services/document-intelligence/language-support/custom) для получения текущей поддержки) |
| **Поддерживаемые функции** | Пары "ключ-значение", метки выбора, таблицы, области, подписи | Перекрывающиеся поля, распознавание подписей, уверенность в определении таблиц, строк и ячеек |

Совет.

Если ваши формы имеют единообразный визуальный вид, начните с использования пользовательской модели на основе шаблона. Обучение такой модели происходит быстрее и обходится дешевле. Если требуемая точность недостаточна или форматы ваших документов различаются, переключитесь на использование пользовательской нейронной сети.

### Специализированные классификаторы.

Специализированные модели классификации определяют тип документа перед тем, как будет запущена модель извлечения данных. Вы можете использовать классификатор для направления поступающих документов к соответствующей модели извлечения, когда вам необходимо обрабатывать документы различных типов.

## Обучите собственную модель.

Для обучения пользовательской модели извлечения данных:

1. Сохраняйте примеры форм в контейнере хранилища Azure Blob Storage вместе с файлами JSON, содержащими информацию о макете и полях формы.
   - А. `ocr.json` файл для каждой заполненной формы (созданный с помощью функции "Анализ документа").
   - Один. `fields.json` файл, в котором описаны поля, которые вы хотите извлечь.
   - A. `labels.json` Файл для каждой формы образца, который сопоставляет поля с их расположением в этой форме.
2. Сгенерируйте URL-адрес с общим ключом доступа (Shared Access Signature, SAS) для этого контейнера.
3. Используйте функцию REST API "Создать модель" или соответствующий метод SDK.
4. Используйте функцию REST API "Получить модель" для получения идентификатора обученной модели.

Вы также можете обучать собственные модели визуально с помощью среды разработки Document Intelligence, как описано в разделе "*Использование среды разработки Document Intelligence*".

Совет.

Используйте не менее пяти-шести образцов форм для обучения. Чем больше и разнообразнее набор данных, тем точнее будут созданные модели.

## Используйте собственную модель.

Чтобы извлечь данные из формы с помощью пользовательской модели, вызовите функцию **Анализ документа**, указав идентификатор вашей модели. Для этого можно использовать либо поддерживаемый SDK, либо REST API.

C# (Си-шарп)

```
string endpoint = "<endpoint>";
string apiKey = "<apiKey>";
AzureKeyCredential credential = new AzureKeyCredential(apiKey);
DocumentAnalysisClient client = new DocumentAnalysisClient(new Uri(endpoint), credential);

string modelId = "<modelId>";
Uri fileUri = new Uri("<fileUri>");

AnalyzeDocumentOperation operation = await client.AnalyzeDocumentFromUriAsync(WaitUntil.Completed, modelId, fileUri);
AnalyzeResult result = operation.Value;
```

**Python**

```
endpoint = "YOUR_DOC_INTELLIGENCE_ENDPOINT"
key = "YOUR_DOC_INTELLIGENCE_KEY"

model_id = "YOUR_CUSTOM_BUILT_MODEL_ID"
formUrl = "YOUR_DOCUMENT"

document_analysis_client = DocumentAnalysisClient(
    endpoint=endpoint, credential=AzureKeyCredential(key)
)

task = document_analysis_client.begin_analyze_document_from_url(model_id, formUrl)
result = task.result()
```

Удачный ответ должен содержать... `analyzeResult` Объект, содержащий извлеченный контент, и массив страниц, содержащих информацию о документе.

## Собранные модели.

Вы можете объединить несколько пользовательских моделей в одну **композитную модель**. При отправке документа в композитную модель, система Document Intelligence анализирует его, чтобы определить наиболее подходящую компоненту модели, а затем возвращает результаты извлечения данных, полученные с помощью этой компоненты. Этот подход полезен, когда вам необходимо обрабатывать различные типы документов, для каждого из которых требуется своя собственная модель извлечения информации.
