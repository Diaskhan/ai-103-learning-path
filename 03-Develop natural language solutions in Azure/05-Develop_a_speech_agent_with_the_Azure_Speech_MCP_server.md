# Разработайте голосового агента с использованием сервера Azure Speech MCP.

# Введение.

Функция Azure Speech в составе инструментов Foundry предоставляет возможности преобразования речи в текст и текста в речь, которые можно интегрировать в приложения с использованием искусственного интеллекта. Эти функции позволяют транскрибировать аудиозаписи в текст и синтезировать естественную речь на основе текстовых данных.

Хотя вы можете использовать эти возможности напрямую через SDK для работы с речью или REST API, вы также можете предоставить их агенту искусственного интеллекта через сервер **протокола контекста моделей речи Azure (Azure Speech Model Context Protocol - MCP)**. Этот подход позволяет агенту обрабатывать задачи, связанные с речью, на основе запроса пользователя, сформулированного естественным языком, без необходимости написания специального кода для каждой операции с речью.

Например, представьте, что вы работаете в компании, которой необходимо обрабатывать обращения клиентов. Вашей команде нужно транскрибировать записанные телефонные разговоры в текст для анализа и генерировать аудиоответы, которые можно воспроизводить клиентам. Вместо того чтобы создавать отдельные интеграции для транскрипции и синтеза речи, вы можете создать AI-агента, который использует сервер Azure Speech MCP для выполнения обеих задач через единое подключение к инструменту.

В этом модуле вы узнаете, как работает сервер Azure Speech MCP, как подключить его к агенту искусственного интеллекта в платформе Microsoft Foundry и как создать клиентское приложение, которое взаимодействует с этим агентом программным путем.

Примечание.

Мы понимаем, что разные люди предпочитают учиться разными способами. Вы можете пройти этот модуль в формате видео или изучить материалы в виде текста и изображений. Текст содержит более подробную информацию, чем видео, поэтому в некоторых случаях вам может быть полезно использовать его как дополнительный материал к видеолекции.

Примечание.

Сервер Azure Speech MCP в настоящее время находится на стадии публичного предварительного тестирования. Информация, представленная в этом разделе, может быть изменена.

# Понимание работы сервера Azure Speech MCP.

Сервер Azure Speech MCP обеспечивает связь между ИИ-агентами и сервисом Azure Speech в среде Foundry Tools посредством протокола **Model Context Protocol (MCP)**. Прежде чем углубляться в изучение самого сервера Azure Speech MCP, полезно понять, что такое MCP и как он позволяет агентам использовать внешние инструменты.

## Что такое протокол контекста модели?

Протокол контекстного взаимодействия (Model Context Protocol, MCP) — это открытый протокол, определяющий принципы взаимодействия агентов искусственного интеллекта с внешними инструментами, источниками данных и сервисами. MCP использует клиент-серверную архитектуру, состоящую из следующих компонентов:

- **Ведущая программа:** Приложение, в котором работает агент (например, Microsoft Foundry или собственное приложение).
- **Клиент:** Компонент, встроенный в хост-систему, который управляет соединениями с серверами протокола управления (MCP) и обеспечивает взаимодействие с ними.
- **Сервер:** Программа, которая предоставляет инструменты, ресурсы и функции, которые агент может обнаружить и использовать.

Когда агент подключается к серверу MCP, он получает каталог доступных инструментов вместе с описаниями их функций. Затем агент может выбрать подходящий инструмент в зависимости от запроса пользователя. Этот подход называется *динамическим обнаружением инструментов* — агенту не требуется иметь заранее заданные знания о каждом инструменте. Вместо этого, он запрашивает информацию у сервера MCP во время работы, чтобы узнать, какие инструменты доступны.

Ключевым преимуществом платформы MCP для искусственного интеллекта является гибкость. Инструменты можно добавлять, обновлять или удалять на сервере без изменения самого агента. Агент всегда имеет доступ к последним определениям инструментов, что упрощает обслуживание и масштабирование решений, основанных на MCP.

Совет.

Чтобы узнать больше об архитектуре MCP и о том, как создавать собственные интеграции инструментов для работы с MCP, обратитесь к разделу "**".[Integrate MCP Tools with Azure AI Agents](/en-us/training/modules/connect-agent-to-mcp-tools/)Модуль.

## Возможности сервера Azure Speech (сервера для работы с технологией распознавания речи Azure).

Сервер Azure Speech MCP предоставляет два основных функциональных модуля для работы с речью, которые могут быть использованы любым агентом, совместимым с платформой MCP:

| Возможность | Описание |
| --- | --- |
| **Преобразование речи в текст (Распознавание)** | Преобразует аудиофайлы в текст с использованием современных технологий распознавания речи. Поддерживает форматы WAV, MP3, OGG, FLAC, MP4, M4A, AAC и другие распространенные аудиоформаты. Включает возможности выбора языка, подсказки для фраз для повышения точности, фильтрацию ненормативной лексики, а также опции выбора подробных или упрощенных форматов вывода. |
| **Преобразование текста в речь (Синтез)** | Преобразует текстовый ввод в аудиофайлы с естественным звучанием, используя нейронные технологии синтеза речи. Поддерживает несколько языков и голосов (например, ...). `en-US-JennyNeural` или. `en-GB-SoniaNeural`... и генерирует выходной файл в форматах WAV, MP3 или других поддерживаемых форматах.

При подключении сервера Speech MCP к агенту, агент получает доступ к доступным инструментам для работы с речью и их описаниям. На основе запроса пользователя, агент определяет, какой инструмент следует использовать. Например, если пользователь говорит: "Преобразуйте этот аудиофайл в текст", агент вызывает инструмент преобразования речи в текст. Если пользователь говорит: "Сгенерируйте речь из этого текста", агент вызывает инструмент преобразования текста в речь.

## Как агент выбирает инструменты.

Процесс выбора инструментов происходит следующим образом:

1. Пользователь отправляет запрос агенту.
2. Агент анализирует запрос и определяет, какую именно речевую задачу необходимо выполнить.
3. Специалист проверяет доступные инструменты MCP и их описания, чтобы найти наиболее подходящий вариант.
4. Агент вызывает выбранный инструмент через сервер управления компонентами (MCP), передавая ему необходимые входные данные (URL-адрес аудиофайла или текст).
5. Сервер MCP обрабатывает запрос с использованием сервиса Azure Speech и возвращает результаты (текст транскрипции или ссылку на аудиофайл).
6. Агент представляет результаты пользователю в виде ответа, сформулированного на естественном языке.

Этот инструмент автоматически выбирает подходящий метод обработки данных, поэтому вам не нужно писать дополнительный код для определения, требуется ли преобразование речи в текст или текста в речь.

## Требования к хранению.

В отличие от инструментов MCP, работающих только с текстом, сервер Azure Speech MCP работает с аудиофайлами, что требует наличия учетной записи хранения в Azure.

- **Преобразование текста в речь:** Сервер Speech MCP сохраняет созданные аудиофайлы в контейнер хранилища Azure Blob Storage. Ответ агента содержит ссылку на созданный аудиофайл.
- **Преобразование речи в текст:** Агент может транскрибировать аудиофайлы, расположенные по общедоступному URL-адресу или хранящиеся в контейнере Azure Blob Storage, доступ к которому осуществляется с использованием URL-адреса SAS.

При подключении сервера Speech MCP к вашему агенту, вы предоставляете **URL-адрес SAS** для контейнера хранилища данных (blob storage). Этот URL-адрес предоставляет серверу MCP разрешение на чтение и запись файлов в этом контейнере.

Важно.

Относитесь к URL-адресам SAS (Shared Access Signature) как к конфиденциальной информации. Устанавливайте максимально короткий срок действия, ограничивайте их область применения одним контейнером и не включайте их в исходный код, запросы к агентам или записи чатов.

Для использования сервера Azure Speech MCP с агентом вам необходимо:

- Подписка Azure.
- Ресурс и проект Foundry – для работы с ними необходимы права участника (Contributor) или владельца (Owner) в соответствующей группе ресурсов. Ваш ресурс Foundry включает в себя функции распознавания речи.
- Учетная запись Azure Storage с контейнером для хранения бинарных больших объектов (blobs), предназначенным для хранения аудиофайлов.

## Вопросы безопасности.

Сервер Azure Speech MCP использует аутентификацию на основе ключей. При создании подключения необходимо указать ваш ключ ресурса и URL-адрес контейнера хранилища с токеном подписи (SAS). Рекомендуется следовать следующим рекомендациям:

- Храните ключи и URL-адреса SAS в защищенном хранилище секретов и регулярно их обновляйте.
- Избегайте прямого указания ключей или URL-адресов SAS в исходном коде, скриптах или документации.
- Используйте максимально короткий допустимый срок действия правила безопасности (SAS) и применяйте его только к минимально необходимому ресурсу.
- Немедленно замените ключи, если у вас есть подозрения, что они могли быть скомпрометированы.

# Подключите и используйте сервер Speech MCP с агентом.

После того как вы ознакомитесь с возможностями сервера Azure Speech MCP, следующим шагом будет его подключение к агенту и начало использования. Это включает в себя настройку хранилища данных, создание агента в Microsoft Foundry, подключение инструмента Speech MCP, тестирование его работы в среде разработки агента и, при необходимости, разработку клиентского приложения.

## Настройка хранилища BLOB-объектов Azure.

Сервер Azure Speech MCP требует наличие учетной записи хранения Azure для хранения аудиофайлов. Перед подключением инструмента необходимо создать учетную запись хранения и контейнер хранилища (blob container).

1. В течение... [Azure portal](https://portal.azure.com)Создайте новую учетную запись хранения Azure (или используйте существующую).
2. В учетной записи хранения разверните раздел "**Хранилище данных**" и выберите "**Контейнеры**".
3. Создайте новый контейнер (например, с именем **files**), в котором будут храниться аудиофайлы, которые ваш агент генерирует и воспроизводит.
4. Сгенерируйте **токен SAS** для контейнера со следующими разрешениями: чтение, добавление, создание, запись и просмотр списка. Установите срок действия токена на максимально короткий разумный период.

Важно.

Скопируйте сгенерированный URL-адрес для SAS и сохраните его в надежном месте, так как он потребуется при подключении сервера Speech MCP.

## Создайте проект и агента Foundry.

Для использования сервера Azure Speech MCP необходимо наличие проекта Microsoft Foundry с развернутой моделью.

1. В течение... [Microsoft Foundry portal](https://ai.azure.com)... создайте новый проект (или используйте существующий).
2. Используйте модель (например, **gpt-4.1**), которую ваш агент будет применять для логических рассуждений и генерации ответов.
3. Создайте агента и предоставьте ему инструкции, описывающие его назначение. Например:

   ```
   You are an AI agent that uses the Azure AI Speech tool to transcribe and generate speech.
   ```

Теперь агент готов принимать подключения инструментов.

## Подключите сервер Azure Speech (Azure Speech Multi-Cloud Platform).

Вы подключаете сервер Azure Speech MCP к вашему агенту через страницу "Инструменты" в портале Foundry.

1. В панели навигации выберите раздел "**Инструменты**".
2. Выберите пункт **Подключить инструмент** и выберите **Azure Speech в разделе "Инструменты Foundry"** из каталога.
3. Настройте соединение, используя следующие параметры:

   - **Название ресурса Foundry:** Название вашего ресурса Foundry (например, ...). `myproject-resource`).
   - **Носитель** (или **держатель**)`Ocp-Apim-Subscription-Key`Ключ для вашего проекта Foundry.
   - **X-Blob-Container-Url**: URL для доступа к вашему контейнеру блобов, использующий механизм общих ключей доступа (SAS).
4. Дождитесь установления соединения, затем выберите пункт "**Использовать в агенте**" и укажите нужного вам агента.

![Скриншот каталога инструментов в портале Foundry, демонстрирующий конфигурацию подключения к сервису Azure Speech в разделе "Инструменты Foundry".](https://learn.microsoft.com/en-us/training/wwl-data-ai/develop-speech-agent-speech-mcp/media/azure-speech-tool-config.png)

Теперь агент имеет доступ к инструментам преобразования речи в текст и текста в речь, предоставляемым сервером Azure Speech MCP.

Совет.

Вы можете найти ключ проекта на главной странице проекта в портале Foundry.

## Тестирование в среде для разработчиков.

Инструмент для тестирования агентов в портале Foundry предоставляет интерактивную среду, позволяющую проверить работу вашего агента.

### Тестовый пример преобразования текста в речь.

Введите запрос, который предписывает агенту сгенерировать речь.

```
Generate "To be or not to be, that is the question." as speech
```

При первом использовании агентом инструмента Speech MCP, вам будет предложено **подтвердить** его использование. Вы можете выбрать опцию "**Всегда подтверждать использование всех инструментов Azure Speech MCP**", чтобы избежать повторных запросов на подтверждение в будущем.

В ответе содержится ссылка на созданный аудиофайл, сохраненный в вашем хранилище данных (blob storage). Выберите эту ссылку, чтобы прослушать синтезированную речь.

### Тестирование функции преобразования речи в текст.

Введите запрос, в котором попросите агента преобразовать аудиофайл в текст. Вы можете использовать общедоступный URL-адрес или URL-адрес SAS, указывающий на файл, расположенный в вашем хранилище объектов (blob storage):

```
Transcribe the file at https://example.com/audio/meeting-recording.wav
```

Агент вызывает функцию преобразования речи в текст и возвращает полученный текстовый результат.

### Настройка голосового вывода.

Инструменты Speech MCP поддерживают несколько параметров, которые вы можете указать в своих запросах:

- **Выбор голоса:** Укажите нейронный голос, например... `en-GB-SoniaNeural` или. `en-US-JennyNeural`.
- **Язык:** Укажите язык для распознавания или синтеза (например, ...). `es-ES` для испанского языка).
- **Подсказки для фраз:** Предоставляйте специализированные термины, чтобы повысить точность транскрипции (например, "Azure, OpenAI, Cognitive Services").
- Фильтрация ненормативной лексики: Запрос. `masked`, `removed`или `raw` Обработка ненормативной лексики во время транскрибации.

Например:

```
Synthesize "Better a witty fool, than a foolish wit!" as speech using the voice "en-GB-SoniaNeural".
```

## Создайте клиентское приложение.

Хотя среда для тестирования агентов полезна для экспериментов, обычно вам необходимо создать клиентское приложение, которое использует программу-агента программным образом. SDK Microsoft Foundry поддерживает это с помощью API OpenAI Responses.

Для создания клиентского приложения необходимо использовать... `azure-ai-projects` и `azure-identity` пакеты. Общая схема выглядит следующим образом:

1. Создать... `AIProjectClient` используя конечную точку вашего проекта Foundry, а также... `DefaultAzureCredential` (который использует ваши учетные данные Azure CLI в процессе разработки).
2. Получите клиент OpenAI из проекта, вызвав соответствующую функцию. `get_openai_client()`.
3. Звонок. `responses.create()` отправить запрос пользователем к агенту.

Ключевым моментом является то, как вы ссылаетесь на агента – вы указываете его имя в... `extra_body` параметр:

```
response = openai_client.responses.create(
    input=[{"role": "user", "content": user_prompt}],
    extra_body={
        "agent_reference": {
            "name": "Speech-Agent",
            "type": "agent_reference"
        }
    },
)

print(response.output_text)
```

Агент обрабатывает запрос, вызывает соответствующий инструмент преобразования речи (Speech MCP) и возвращает результат в... `output_text`Для запросов преобразования текста в речь вывод содержит ссылку на созданный аудиофайл, расположенный в вашем хранилище данных (blob storage).

### Подключите сервер MCP в коде.

Вместо подключения сервера Azure Speech MCP через портал Foundry, вы можете определить подключение к инструменту MCP непосредственно в коде при создании агента. Используйте... `MCPTool` курс от... / группа из... / класс, сформированный на основе... `azure-ai-projects` SDK: Комплект средств разработки.

```
from azure.ai.projects.models import MCPTool

mcp_tool = MCPTool(
    server_label="azure-speech",
    server_url="https://{foundry-resource-name}.cognitiveservices.azure.com/speech/mcp",
    require_approval="always",
)
```

Затем вы проходите... `mcp_tool` при создании агента с помощью SDK. Этот подход полезен, когда вы хотите управлять подключениями к инструментам в рамках кода вашего приложения, а не настраивать их вручную через портал.
