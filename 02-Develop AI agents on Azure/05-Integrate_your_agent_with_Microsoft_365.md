# Интегрируйте вашего агента с платформой Microsoft 365.

# Введение.

Представьте, что вы разработали AI-агента в платформе Microsoft Foundry, который помогает вашей команде отвечать на вопросы о политиках и процедурах компании. Этот агент отлично работает в тестовой среде Foundry, но ваши пользователи большую часть дня проводят в Microsoft Teams. Они хотят взаимодействовать с агентом непосредственно в чате Teams или даже через Microsoft 365 Copilot, не переключаясь при этом на отдельное приложение. Как вам решить эту проблему?

Microsoft Foundry предоставляет встроенные возможности для прямой публикации ваших агентов в Microsoft Teams и Microsoft 365 Copilot. Эта интеграция позволяет пользователям взаимодействовать с вашими специализированными AI-агентами в тех же инструментах, которые они уже используют для совместной работы и повышения продуктивности. Независимо от того, нужен ли вам агент поддержки, отвечающий на вопросы IT-специалистов, помощник по знаниям, помогающий новым сотрудникам адаптироваться, или специализированный консультант для вашей бизнес-области, вы можете сделать этих агентов доступными там, где работают ваши пользователи.

В этом модуле вы узнаете, как публиковать агентов Microsoft Foundry в Microsoft 365. Вы изучите процесс публикации через портал Foundry, поймете, когда могут потребоваться расширенные возможности интеграции, и узнаете, как использовать Work IQ для предоставления вашим агентам доступа к данным Microsoft 365, таким как электронные письма, встречи и документы.

## Цели обучения.

К концу этого модуля вы сможете:

- Опишите варианты публикации агентов Foundry в Microsoft 365.
- Опубликуйте агента из портала Foundry в приложениях Teams и Microsoft 365 Copilot.
- Используйте Work IQ для доступа к данным Microsoft 365, хранящимся в аккаунтах ваших сотрудников.
- Тестирование и устранение неполадок агентов, интегрированных с Microsoft 365.

- Знакомство с платформой Azure и порталом Azure.
- Опыт разработки агентов в платформе Microsoft Foundry (рекомендуется:). [Develop AI agents with Microsoft Foundry and Visual Studio Code](/en-us/training/modules/develop-ai-agents-azure-vs-code/) модуль)
- Подписка на Microsoft 365 с доступом к приложению Teams.

# Ознакомьтесь с вариантами публикации контента через агента Foundry.

При создании агента в Microsoft Foundry он работает в инфраструктуре сервиса Foundry Agent. Публикация позволяет преобразовать ваш агент из объекта разработки в управляемый ресурс Azure с выделенным интерфейсом, независимой идентификацией и возможностями управления.

## Понимание принципов работы приложений для агентов.

При публикации агента, платформа Microsoft Foundry создает ресурс под названием "**Приложение агента**", который включает в себя:

- **Выделенный URL-адрес для вызова:** Стабильный адрес, который остается неизменным при обновлении версий агента.
- **Идентификатор приложения:** Уникальный идентификатор приложения Microsoft Entra, отличный от вашего проекта разработки.
- **Изоляция данных пользователей:** Данные и действия одного пользователя недоступны другим пользователям.

Приложение для агентов выполняет функцию маршрутизации. При публикации новой версии агента трафик автоматически перенаправляется на обновленную версию без изменения публичного адреса.

## Публикация в Microsoft 365.

Основной целью этого модуля является интеграция с Microsoft 365, которая позволяет вашим сотрудникам взаимодействовать непосредственно в приложениях Teams и Copilot. Публикация данных в Microsoft 365:

- Создает ресурс службы Azure Bot, который перенаправляет сообщения между Microsoft 365 и вашим агентом.
- Создает пакет для публикации в Microsoft 365, предназначенный для распространения.
- Регистрирует приложение для идентификации в службе Microsoft Entra ID для целей аутентификации.
- Позволяет сделать вашего агента доступным в магазине агентов для Microsoft Teams.

### Прямая публикация материалов с портала Foundry.

Самый простой способ – это публикация непосредственно через портал Foundry. Мастер публикации позволяет:

1. Создает ресурс службы ботов Azure в вашей подписке.
2. Зарегистрируйте приложение в службе Microsoft Entra ID.
3. Создает пакет для публикации в Microsoft 365.
4. Подготавливает вашего агента к распространению.

Этот подход идеально подходит, когда вам нужно быстро развернуть систему или полностью интегрировать логику работы вашего агента в платформу Foundry.

### Набор инструментов для специалистов поддержки Microsoft 365.

Для сложных сценариев вы можете использовать набор инструментов Microsoft 365 Agents Toolkit для создания прокси-приложения, которое подключается к вашему агенту Foundry. Рассмотрите этот подход, если вам требуется настройка единой точки входа (SSO), расширенная логика промежуточного программного обеспечения или развертывание приложений в нескольких средах. О наборе инструментов Agents Toolkit будет рассказано позже в этом разделе как об опциональной, более сложной теме.

### Области публикаций.

При публикации контента в Microsoft 365 вы можете выбрать один из двух вариантов распространения:

| Область применения | Описание | Рекомендуется для |
| --- | --- | --- |
| **Общий доступ** | Доступен немедленно без одобрения администратора. Отображается в разделе "Ваши агенты" в Teams. | Для личного тестирования, для пилотных проектов небольших команд. |
| **Организация** | Доступно всем пользователям вашей организации в разделе "**Создано вашей организацией**". Требуется одобрение администратора. | Продуктивные среды развертывания |

## Другие каналы распространения информации.

Хотя этот модуль посвящен платформе Microsoft 365, агенты Foundry также могут публиковать контент на следующих ресурсах:

- **Предварительный просмотр веб-приложения:** Интерфейс, работающий в браузере, предназначенный для демонстраций и тестирования со стороны заинтересованных сторон.
- **Стабильный конечный пункт API:** REST API для интеграции в собственные приложения.
- **Каналы Azure Bot Service:** Slack, Telegram, Twilio (SMS), Facebook и другие.

Эти варианты полезны, когда вам необходимо связаться с пользователями, не использующими Microsoft 365, или интегрировать вашего агента в собственные приложения.

## Идентификация агента и его права доступа.

При публикации агента система создает для него уникальную идентификацию. Это важно по следующим причинам:

- Агент аутентифицируется для доступа к ресурсам Azure, используя свои собственные учетные данные.
- Права доступа, установленные для вашего проекта во время разработки, не переносятся автоматически.
- Инструменты, использующие сервисы Azure, требуют перенастройки прав доступа после публикации.

Если ваш агент использует инструменты, которые подключаются к сервисам, таким как Azure AI Search, предоставьте учетной записи этого агента необходимые права доступа.

## Необходимые условия для публикации.

Перед публикацией агента в Microsoft 365 убедитесь, что у вас есть следующее:

- Должность руководителя проекта Azure AI в рамках вашего проекта Foundry.
- Роль "Пользователь Azure AI" в области применения приложения агента.
- Подписка Azure, в рамках которой можно создавать ресурсы службы Azure Bot Service.
- Разрешения для регистрации приложений в Microsoft Entra ID.
- Подписка Microsoft 365, которая позволяет использовать собственные приложения и боты.

# Опубликуйте агента из портала Foundry в Teams.

Публикация агента из портала Microsoft Foundry в Microsoft Teams и Microsoft 365 Copilot – это простой процесс. Портал предоставляет пошаговые инструкции по созданию приложения для агента, настройке необходимых ресурсов Azure и формированию пакета для распространения.

## Прежде чем начать.

Перед началом процесса публикации необходимо выполнить следующие подготовительные шаги:

### Тщательно протестируйте ваше программное обеспечение.

Используйте тестовую среду Foundry, чтобы убедиться, что ваш агент работает так, как ожидается. Проверьте различные варианты ввода данных пользователем, убедитесь, что все настроенные инструменты функционируют правильно, и проверьте, соответствуют ли ответы вашим потребностям. Устранять проблемы гораздо проще до публикации, чем после нее.

### Проверьте свои права доступа.

Пожалуйста, убедитесь, что у вас есть необходимые права доступа.

- Должность руководителя проекта Azure AI в рамках вашего проекта Foundry для публикации агентов.
- Роль "Пользователь Azure AI" для вызова или общения с опубликованными агентами.
- Разрешения на создание ресурсов в вашей подписке Azure.
- Разрешения для регистрации приложений в Microsoft Entra ID.

### Зарегистрируйте поставщика услуг ботов.

Процесс публикации создает ресурс службы ботов Azure. Убедитесь, что поставщик ресурсов **Microsoft.BotService** зарегистрирован в вашей подписке Azure. Вы можете проверить это в портале Azure в разделе "Поставщики ресурсов" вашей подписки.

### Подготовьте метаданные.

Прежде чем начать, соберите следующую информацию:

- Название вашего агента, которое будет отображаться в магазине агентов Microsoft Teams.
- Краткое описание того, чем занимается ваш агент.
- Небольшие (32x32 пикселя) и большие (192x192 пикселя) значки в формате PNG.
- Наименование вашей организации и контактные данные.
- Ссылки на вашу политику конфиденциальности и условия использования.

Предупреждение.

Не включайте в поля метаданных конфиденциальную информацию, такие как секреты, ключи API или другие чувствительные данные. Эти поля видны пользователям, которые находят вашего агента.

## Опубликуйте информацию о вашем агенте.

Следуйте этим шагам, чтобы опубликовать вашего агента через портал Foundry:

### Шаг 1: Выберите версию агента.

1. Откройте. [Microsoft Foundry portal](https://ai.azure.com) и перейдите в нужный вам проект.
2. Выберите агента, которого вы хотите опубликовать, из списка доступных агентов.
3. Проверьте настройки агента, чтобы убедиться, что он готов к публикации.

### Шаг 2: Начните процесс публикации.

1. Нажмите кнопку "**Опубликовать**", чтобы открыть окно публикации.
2. Выберите еще раз пункт **Опубликовать**, а затем выберите **Опубликовать в Teams и Microsoft 365 Copilot**.
3. Открывается окно настроек публикации для Microsoft 365.

### Шаг 3: Настройка службы Azure Bot Service.

1. Портал автоматически генерирует идентификатор приложения и идентификатор арендатора. Запомните эти значения для устранения неполадок.
2. В раскрывающемся списке **Служба ботов Azure** выберите пункт **Создать службу ботов Azure**, чтобы создать новый ресурс для бота.
3. Подождите, пока портал создаст ресурс "Bot Service" в вашей подписке.

### Шаг 4: Заполните метаданные.

Заполните необходимые поля:

| Поле | Описание |
| --- | --- |
| **Название** | Отображаемое имя вашего приложения в магазине приложений Microsoft Teams. |
| **Описание** | Краткое описание того, что делает ваш агент |
| **Иконки** | Загрузка небольших и крупных значков в формате PNG |
| **Информация об издателе** | Наименование вашей организации и контактные данные |
| **Политика конфиденциальности** | Ссылка на политику конфиденциальности вашей организации |
| **Условия использования** | Ссылка на ваши условия предоставления услуг |

### Шаг 5: Выберите область распространения публикации.

Выберите область распространения для вашего агента:

- **Область применения:** Агент отображается в разделе "Ваши агенты" в магазине. Доступен немедленно. Рекомендуется для тестирования и небольших команд.
- **Область применения:** Этот компонент отображается в магазине под заголовком "Создано вашей организацией". Требуется одобрение администратора. Рекомендуется для использования в производственной среде.

### Шаг 6: Подготовьте и, при необходимости, загрузите пакет.

1. Выберите пункт "**Подготовить агент**", чтобы начать процесс упаковки вашего агента.
2. Подождите, пока процесс упаковки завершится (обычно это занимает 1-2 минуты).
3. Когда вы будете готовы, вы можете:
   - Загрузите пакет и протестируйте его локально перед распространением.
   - Продолжить процесс публикации внутри приложения для прямой распространения.

## Протестируйте пакет инструментов для публикации в Microsoft Teams.

Если вы загрузили пакет, протестируйте его в Microsoft Teams перед тем, как распространять его среди широкого круга пользователей.

1. Откройте приложение Microsoft Teams.
2. Перейдите в раздел **Приложения** > **Управление приложениями** > **Загрузить приложение**.
3. Выберите пункт "**Загрузить собственное приложение**" и выберите скачанный файл. `.zip` файл.
4. Команда устанавливает приложение и отображает его в списке установленных приложений.
5. Откройте приложение и отправьте тестовое сообщение.

Пожалуйста, проверьте следующее:

- [ ] Агент отвечает на сообщения.
- [ ] Содержание ответа является точным и уместным.
- [ ] Время отклика приемлемо.
- [ ] Все настроенные инструменты работают корректно.

## Запросите одобрение администратора для определения области действия организации.

Если вы опубликовали информацию в рамках определенной организации, администратор должен утвердить вашего агента, прежде чем он станет доступен для всех сотрудников этой организации.

1. Пожалуйста, сообщите вашему администратору Microsoft 365 о следующем: [Microsoft 365 admin center](https://admin.cloud.microsoft).
2. Перейдите в раздел "**Агенты**" > "**Все**" > "**Запросы**".
3. Найдите своего агента в списке ожидающих обработки запросов.
4. Администратор выбирает опцию "**Подтвердить запрос и активировать**".

После утверждения агент появляется в разделе "**Создано вашей организацией**" магазина агентов Microsoft Teams для всех пользователей в вашем арендаторе. Политики приложений, действующие в вашей организации, определяют, какие пользователи могут получить доступ к данному агенту.

## Измените права доступа после публикации.

При публикации агента система создает для него уникальную идентификацию. Если ваш агент использует инструменты, которые получают доступ к ресурсам Azure, вам необходимо предоставить этому новому идентификатору соответствующие разрешения:

1. В портале Foundry перейдите к вашему опубликованному агенту и запишите информацию об идентификации этого агента.
2. В портале Azure перейдите к ресурсам, к которым имеет доступ ваш агент (например, Azure AI Search, учетные записи хранения или Cosmos DB).
3. Назначьте соответствующие роли управления доступом на основе ролей (RBAC) опубликованному идентификатору агента.

Без этого этапа инструменты, которые работали во время разработки, могут перестать функционировать после публикации, поскольку новая учетная запись агента не обладает необходимыми разрешениями.

## Обновить информацию об опубликованном агенте.

При внесении изменений в ваш агент в системе Foundry необходимо повторно опубликовать его, чтобы обновить версию, доступную в Teams.

1. Внесите необходимые изменения в портале Foundry.
2. Протестируйте внесенные изменения в тестовой среде Foundry.
3. Повторите процесс публикации, чтобы создать новый пакет.
4. Для общих областей видимости загрузите новый пакет в Microsoft Teams.
5. В зависимости от политики вашей организации, для применения обновления может потребоваться повторное утверждение в рамках определенной структуры.

Пользователи, взаимодействующие с вашим агентом, получат обновленную версию сразу после развертывания нового пакета.

# Расширенный уровень – используйте набор инструментов Microsoft 365 для специалистов поддержки.

В большинстве случаев самый простой способ подключить ваши агенты к Microsoft Teams и Microsoft 365 Copilot — это публикация непосредственно через портал Foundry. Однако, в некоторых сложных корпоративных сценариях может потребоваться более детальный контроль над процессом интеграции. Набор инструментов Microsoft 365 Agents Toolkit предлагает альтернативный подход для таких ситуаций.

Этот раздел предоставляет обзор набора инструментов для агентов. Для более подробного изучения перейдите по ссылкам в конце раздела, где представлена соответствующая документация.

Примечание.

Этот раздел посвящен продвинутой теме. Если вы только начинаете работу с интеграцией агентов Foundry, вы можете пропустить этот раздел и вернуться к нему позже, если столкнетесь со сценариями, требующими использования инструментария Agents Toolkit.

## Когда следует использовать набор инструментов для агентов?

Набор инструментов для разработки агентов Microsoft 365 – это комплекс средств разработки, доступных в виде расширений для Visual Studio Code и Visual Studio. Рекомендуется использовать этот набор, когда вашему агенту требуется нестандартная настройка единой точки входа (SSO), выходящая за рамки стандартной конфигурации Entra ID, или когда вам необходимо добавить промежуточное программное обеспечение для выполнения пользовательской обработки, ведения журналов или преобразования данных между Teams и вашим агентом Foundry.

Этот набор инструментов также полезен для организаций, которым требуется развертывание в различных средах с отдельными конфигурациями для разработки, тестирования и производства. Он предоставляет расширенные возможности отладки с подробным трассированием, превосходящие те, которые предлагает портал Foundry, и интегрируется с конвейерами CI/CD через GitHub Actions или Azure DevOps.

## Как работает подход "Набор инструментов для агентов".

Вместо прямой публикации из Foundry, вы создаете промежуточное приложение с помощью набора инструментов Agents, которое располагается между Microsoft 365 и вашим агентом Foundry:

```
Teams/Copilot → Proxy App (Agents Toolkit) → Foundry Agent
```

Это прокси-приложение получает сообщения от Teams или Copilot через службу Azure Bot Service, обрабатывает их с помощью настроенных вами промежуточных компонентов, пересылает запрос вашему агенту Foundry и возвращает ответ тем же путем. Использование прокси позволяет вам контролировать каждый этап обработки сообщений, но при этом усложняет процесс развертывания.

# Получите доступ к данным Microsoft 365 с помощью Work IQ.

При создании программных агентов, которые помогают пользователям в решении рабочих задач, доступ к организационным данным может значительно повысить их полезность. Сервис Microsoft Work IQ предоставляет возможность подключения искусственного интеллекта к данным Microsoft 365, включая электронные письма, встречи, документы, сообщения в Teams и информацию о сотрудниках.

## Что такое "Work IQ"?

Microsoft Work IQ – это интерфейс командной строки (CLI) и сервер, который связывает ИИ-ассистентов с данными Microsoft 365 Copilot. Он позволяет пользователям запрашивать информацию о рабочей среде, используя естественный язык, предоставляя богатый контекст, что помогает ассистентам давать более релевантные и точные ответы.

С помощью Work IQ ваши сотрудники смогут отвечать на такие вопросы, как:

- "Что мой руководитель сказал о сроках завершения проекта?"
- "Найдите мои последние документы, касающиеся планирования на четвертый квартал."
- "Пожалуйста, кратко изложите основные сообщения, опубликованные сегодня в канале для инженеров."
- "Кто работает над проектом "Альфа"?"

Work IQ получает доступ к данным из различных сервисов Microsoft 365:

| Тип данных | Примеры возможностей |
| --- | --- |
| **Электронная почта** | Поиск сообщений, поиск переписки с конкретными людьми. |
| **Встречи** | Проверьте календарь, ознакомьтесь с протоколами встреч и принятыми решениями. |
| **Документы** | Поиск файлов в SharePoint и OneDrive, поиск по содержимому. |
| **Сообщения в командах** | Краткое изложение обсуждений в каналах, поиск конкретных разговоров. |
| **Люди** | Определяйте участников команды, находите коллег для совместной работы над проектами. |

## Понимание работы серверов MCP.

Work IQ основан на **протоколе контекстной модели (Model Context Protocol, MCP)**, открытом протоколе, который позволяет ИИ-ассистентам подключаться к внешним источникам данных и инструментам. Понимание принципов работы MCP помогает объяснить, как функционирует Work IQ.

Сервер MCP предоставляет возможности, которые могут быть использованы агентами искусственного интеллекта. Эти возможности могут включать в себя:

- **Инструменты:** Действия, которые агент может выполнять, например, поиск документов или отправка сообщений.
- **Источники данных:** Базы данных и другие источники информации, к которым агент может обращаться для получения данных.
- **Шаблоны:** Заранее определенные шаблоны для типовых запросов.

При настройке сервера MCP для вашего агента, агент определяет, какие инструменты и ресурсы доступны, и может использовать их для выполнения запросов пользователей. Work IQ выступает в качестве сервера MCP, специально разработанного для работы с данными Microsoft 365.

## Как работает платформа Work IQ.

Программа Work IQ работает в двух режимах:

### Режим работы через командную строку.

В режиме командной строки вы можете выполнять запросы непосредственно из терминала.

```
workiq ask -q "What requirements did Sarah share about the authentication feature?"
```

Этот режим полезен для быстрых запросов во время разработки или для скриптов, которым необходимо получать информацию о рабочей среде.

### Режим работы сервера MCP.

В режиме работы сервера MCP, система Work IQ интегрируется с ИИ-ассистентами, такими как GitHub Copilot в среде разработки Visual Studio Code. Ваш ИИ-ассистент может автоматически получать доступ к контексту рабочей среды, когда это необходимо для выполнения ваших задач.

Например, если вы реализуете функцию, которая обсуждалась на недавней встрече, ваш искусственный интеллект может получить доступ к информации с этой встречи, чтобы предоставить более релевантные предложения.

## Установка Work IQ.

Вы можете установить программу Work IQ несколькими способами, в зависимости от того, какой способ работы вам наиболее удобен.

### Установите с помощью npm.

```
# Global installation
npm install -g @microsoft/workiq

# Or run directly without installation
npx -y @microsoft/workiq mcp
```

### Установите с помощью интерфейса командной строки GitHub Copilot.

Если вы используете интерфейс командной строки GitHub Copilot (GitHub Copilot CLI), вы можете установить Work IQ в качестве плагина:

1. Для запуска интерфейса командной строки GitHub Copilot выполните следующую команду: `copilot`.
2. Добавьте магазин плагинов (единоразовая настройка): `/plugin marketplace add github/copilot-plugins`
3. Установите Work IQ: `/plugin install workiq@copilot-plugins`
4. Перезапустите командную строку Copilot и начните запрашивать данные из вашей системы Microsoft 365.

### Настройка для Visual Studio Code.

Вы можете добавить Work IQ в качестве сервера MCP через настройки VS Code. Добавьте следующее в вашу конфигурацию MCP:

```
{
  "workiq": {
    "command": "npx",
    "args": [
      "-y",
      "@microsoft/workiq",
      "mcp"
    ],
    "tools": [
      "*"
    ]
  }
}
```

Перед первым использованием необходимо принять условия лицензионного соглашения для конечного пользователя:

```
workiq accept-eula
```

## Необходимые условия для прохождения теста на оценку интеллектуальных способностей (IQ).

Для использования программы Work IQ вам необходимо:

- Установленный на вашем компьютере Node.js (если вы используете командную строку локально).
- Подписка на Microsoft 365 с лицензией Copilot.
- Разрешение администратора для использования приложения Work IQ в вашем экземпляре Microsoft Entra.

Важно.

Функция Work IQ требует административного разрешения, поскольку она получает доступ к данным Microsoft 365, используемым во всей организации. Если вы не являетесь администратором вашей учетной записи, обратитесь в свой отдел информационных технологий для запроса доступа.

## Безопасность и доступ к данным.

Work IQ унаследовал модель безопасности от Microsoft 365 Copilot:

- **Доступ на основе разрешений:** Work IQ может получать доступ только к тем данным, которые вам уже разрешено просматривать.
- **Отсутствие хранения данных:** Work IQ не хранит ваши данные Microsoft 365; он извлекает информацию по запросу.
- **Безопасность корпоративных данных:** Доступ ко всем данным осуществляется в соответствии с политиками безопасности вашей организации.
- **Видимость для администраторов:** Администраторы могут отслеживать и контролировать использование Work IQ.

При запросе информации в системе Work IQ она получает данные через Microsoft Graph, используя вашу аутентифицированную учетную запись. Это означает следующее:

- Вы не можете получить доступ к документам, если у вас нет прав для их просмотра.
- Запросы могут быть просмотрены и отслежены вашей организацией.
- Политики защиты данных распространяются на запросы в системе Work IQ.

## Использование Work IQ для развития сотрудников.

Work IQ помогает вам понять контекст, в котором работают ваши пользователи, при разработке агентов. Вы можете взаимодействовать с Work IQ через командную строку (CLI) или сервер MCP, в зависимости от вашего рабочего процесса.

### Подход, основанный на интерфейсе командной строки (CLI).

Интерфейс командной строки (CLI) полезен для быстрых, разовых запросов во время разработки. Запустите... `workiq ask` выполните команду непосредственно из вашей командной строки:

```
# Find project context
workiq ask -q "What were the key decisions in last week's architecture review meeting?"

# Understand requirements from documents
workiq ask -q "Summarize the requirements in the user portal spec document"

# Check team communications
workiq ask -q "What has the engineering team discussed about the API changes?"
```

Подход с использованием командной строки хорошо подходит для написания скриптов, выполнения разовых запросов или когда вам нужны быстрые ответы без необходимости открывать интегрированную среду разработки (IDE).

### Подход с использованием сервера MCP (Message Control Protocol).

Когда Work IQ работает в качестве сервера MCP, ваш ИИ-помощник может автоматически получать доступ к тем же данным Microsoft 365. Вместо использования команд интерфейса командной строки, вы взаимодействуете с вашим ИИ-помощником естественным образом, а он, в свою очередь, использует инструменты Work IQ в фоновом режиме.

Например, в редакторе VS Code с настроенным GitHub Copilot, использующим технологию Work IQ:

- Задайте вопрос Copilot: "Какие требования Сара озвучила относительно функции аутентификации?"
- Copilot использует инструменты MCP от Work IQ для запроса данных из вашей системы Microsoft 365.
- Вы получаете ответ в чате, не выполняя никаких команд.

Подход MCP органично интегрирует контекст рабочей среды в ваш процесс разработки. Ваш виртуальный помощник определяет, когда следует запросить информацию из системы Work IQ, основываясь на ваших вопросах, что делает взаимодействие более естественным и не требует явных команд.

Оба подхода обеспечивают доступ к одним и тем же базовым данным с использованием одних и тех же прав доступа. Вы можете использовать интерфейс командной строки (CLI) для написания скриптов и быстрых запросов в терминале, или сервер MCP для получения расширенных возможностей, включая интеграцию с интеллектуальным помощником.

Примечание.

В настоящее время Work IQ находится на стадии предварительного тестирования. Функциональность и API могут изменяться по мере развития продукта.

После публикации вашего агента, следуя инструкциям из предыдущих разделов, постоянное тестирование и мониторинг помогут обеспечить надежную работу агента для пользователей. ## Тестирование за пределами тестовой среды Foundry.

Платформа Foundry полезна для тестирования и разработки, но она не полностью имитирует конечный пользовательский опыт после публикации. После публикации протестируйте своего агента в Microsoft Teams, чтобы убедиться в следующем:

- Пользовательский интерфейс приложения Teams корректно отображает ответы.
- Процессы аутентификации работают корректно.
- Время отклика приемлемо в производственной среде.
- Идентичность агента, опубликованная в системе, имеет необходимые права доступа.

### Тестирование с участием нескольких пользователей.

Попросите коллег протестировать вашего чат-бота, чтобы выявить проблемы, которые вам могут быть незаметны. Разные пользователи формулируют вопросы по-разному, и свежий взгляд может помочь обнаружить непонятные ответы. Тестирование на различных клиентах Teams (настольном компьютере, в веб-браузере, на мобильных устройствах) также может выявить проблемы, специфичные для конкретной платформы.

## Наиболее распространенные сценарии устранения неполадок.

В случае возникновения проблем, следующие распространенные сценарии и способы их решения могут быть полезны:

### Агент не отвечает в Microsoft Teams.

Возможные причины:

- Служба Azure Bot в данный момент не работает.
- Конфигурация сервиса бота настроена неправильно.
- Проблемы с сетевым подключением между приложением Teams и вашим агентом.

**Решение:**

1. Убедитесь, что ресурс "Bot Service" существует в портале Azure.
2. Проверьте журналы работы сервиса Check Bot на наличие ошибок.
3. Убедитесь, что агент успешно опубликован и пакет был загружен корректно.

### Инструменты работают в программе Foundry, но не функционируют в Teams.

Возможная причина: У опубликованного идентификатора агента отсутствуют необходимые права доступа.

**Решение:**

1. Найдите информацию об идентификаторе агента, указанного в опубликованном отчете, в портале Foundry.
2. В портале Azure найдите ресурсы, к которым обращаются ваши инструменты.
3. Назначьте соответствующие роли управления доступом на основе ролей (RBAC) опубликованному идентификатору агента.

### Пользователи не могут найти агента.

Возможные причины:

- Выбран неверный диапазон публикации.
- Одобрение со стороны администрации ожидается (для определения области деятельности организации).
- Политики, установленные администраторами организации, могут блокировать использование сторонних приложений.

**Решение:**

- Для общего доступа: предоставьте пользователям прямую ссылку.
- Для организации: убедитесь, что администратор дал свое согласие в центре администрирования Microsoft 365.
- Проверьте настройки арендатора для пользовательских разрешений приложений.

### Собирать отзывы пользователей.

- Регулярно анализируйте отзывы, чтобы выявить наиболее распространенные проблемы.
- Используйте обратную связь для определения приоритетных направлений улучшения работы сотрудников.

## Улучшение и доработка вашего агента.

При обнаружении проблем в ходе тестирования или получении обратной связи от пользователей, обновите свой агент в портале Foundry и повторно опубликуйте его, следуя той же процедуре, описанной в разделе о публикации. Для развертываний на уровне организации проверьте политики вашей учетной записи, чтобы определить, требуется ли повторное утверждение обновлений.
