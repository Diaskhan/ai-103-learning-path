# Разработайте программного агента на основе платформы Microsoft Agent Framework.

# Введение.

Искусственные интеллект-агенты используют генеративный искусственный интеллект для анализа данных, принятия решений и выполнения задач с минимальным участием человека, что делает их идеальными для автоматизации сложных процессов. Для эффективной разработки таких агентов разработчикам необходима платформа, которая сочетает в себе простоту использования и надежность, соответствующую корпоративным стандартам.

**Фреймворк Microsoft Agent Framework** представляет собой следующее поколение технологий Semantic Kernel и AutoGen, разработанных одними и теми же командами. Он объединяет простые механизмы работы с агентами, реализованные в AutoGen, с корпоративными функциями Semantic Kernel — управлением состоянием на основе сессий, типобезопасностью, промежуточным программным обеспечением и телеметрией — и добавляет графовые рабочие процессы для явной координации работы нескольких агентов. В результате получается гибкий SDK, готовый к использованию в производственной среде, для создания как одноагентных, так и многоагентных решений.

Этот модуль посвящен использованию фреймворка Microsoft Agent и сервиса Microsoft Foundry Agent Service для создания искусственных интеллектуальных агентов. Предположим, вам необходимо разработать агент, который извлекает данные из представленных отчетов о расходах, правильно их форматирует и отправляет по электронной почте соответствующим получателям. Инструменты интеграции и функции управления сеансами фреймворка Agent позволяют легко реализовать подобный процесс.

В этом модуле вы узнаете об основных особенностях SDK для платформы Microsoft Agent и о том, как создавать ИИ-агентов с использованием инструментов.

После завершения этого модуля вы сможете:

- Используйте платформу Microsoft Agent для подключения к проекту Microsoft Foundry.
- Создавайте агентов Microsoft Foundry с использованием платформы Microsoft Agent Framework.
- Интегрируйте функции инструментов с вашим ИИ-агентом.

Примечание.

Мы понимаем, что разные люди предпочитают учиться разными способами. Вы можете пройти этот модуль в формате видео или изучить материалы в виде текста и изображений. Текст содержит более подробную информацию, чем видео, поэтому в некоторых случаях вам может быть полезно использовать его как дополнительный материал к видеолекции.

# Понимание принципов работы искусственного интеллекта в компоненте Microsoft Agent Framework.

Фреймворк **Microsoft Agent Framework** представляет собой следующее поколение технологий Semantic Kernel и AutoGen, разработанных одними и теми же командами разработчиков. Он объединяет интуитивно понятные механизмы работы с агентами, реализованные в AutoGen, с функциями корпоративного уровня, предлагаемыми Semantic Kernel, включая управление состоянием сеансов, типобезопасность, фильтры выполнения и систему телеметрии.

Предлагаемая система использует графовые структуры для описания рабочих процессов, что позволяет разработчикам иметь полный контроль над путями выполнения задач, выполняемых несколькими агентами. Каждый агент создается на основе единой... `Agent` базовый класс, который обеспечивает единый интерфейс независимо от того, какой именно провайдер моделей вы используете.

## Архитектура и основные особенности.

Вместо того чтобы требовать от вас ручного объединения отдельных библиотек для работы с памятью, интеграции инструментов и доступа к моделям, фреймворк Microsoft Agent объединяет эти компоненты в набор модульных блоков. Вы можете использовать их по отдельности или комбинировать вместе по мере усложнения вашего решения.

| Характеристика | Описание |
| --- | --- |
| **Модели клиентов** | Единый интерфейс для взаимодействия с несколькими поставщиками решений на основе искусственного интеллекта. |
| **Сессия агента** | Встроенное управление состоянием для поддержания контекста разговора в многоступенчатых взаимодействиях. |
| **Поставщики контекстной информации** | Модули памяти, работающие по принципу "подключил и используй", которые динамически предоставляют агентам релевантную информацию. |
| **Инструменты для выполнения функций** | Пользовательские функции, которые автоматически регистрируются в агентах, а генерация схем осуществляется самой платформой. |
| **Клиенты MCP** | Встроенная поддержка протокола Model Context Protocol (MCP), обеспечивающая динамическое обнаружение инструментов во время выполнения. |
| **Промежуточное ПО (Middleware)** | Механизмы для перехвата, логирования или изменения действий агента до и после их выполнения. |
| **Оркестрация рабочих процессов** | Графовые рабочие процессы для управления последовательными, параллельными, групповыми чатами и передачей запросов между операторами. |

## Что могут делать агенты.

Поскольку все агенты используют один и тот же... `Agent` Используя базовый класс, вы получаете набор стандартных функций, независимо от того, какой провайдер обеспечивает работу вашего агента. Это означает, что вы можете сосредоточиться на логике своего приложения, а не на адаптации к специфическим API различных провайдеров.

По умолчанию, каждый агент в этой системе поддерживает следующее:

- **Вызов функций** — автоматическое использование зарегистрированных инструментов для взаимодействия с внешними API и сервисами.
- **Многоступенчатые диалоги:** сохранение истории переписки либо локально, либо с использованием системы управления историей, предоставляемой сервисом.
- **Структурированные выходные данные** — генерирование ответов с соблюдением строгой типизации и валидации по схеме.
- **Потоковая обработка результатов:** Получайте результаты постепенно, по мере их генерации.
- **Инструменты, предоставляемые сервисом:** используйте встроенные возможности, такие как выполнение кода, поиск файлов и веб-поиск, если это поддерживается поставщиком услуг.

## Использование платформы Microsoft Agent с помощью AI Foundry.

Фреймворк Microsoft Agent предназначен для бесперебойной работы с вашими проектами Azure AI Foundry. Он предоставляет унифицированный интерфейс для подключения к Foundry, управления сеансами агентов и интеграции с инструментами и сервисами.

Используя ваши учетные данные Azure для аутентификации, вы можете подключиться к своему проекту Foundry и создавать агентов, которые используют возможности сервиса Foundry Agent. Эти возможности включают в себя сохранение истории чата, динамическое обнаружение инструментов и интеграцию с сервисами Azure.

### Почему компания Foundry является рекомендуемым поставщиком?

Ключевой особенностью сервиса Foundry Agent является поддержка **истории переписки на стороне сервиса**. Благодаря истории, хранящейся на стороне сервиса, сессия оператора автоматически сохраняется между обращениями – вам не нужно самостоятельно управлять состоянием разговора. История переписок на стороне сервиса делает Foundry рекомендуемым поставщиком решений для производственных сценариев, где поддержание контекста является критически важным.

## Матрица поставщиков.

Одним из практических преимуществ унифицированного интерфейса фреймворка "Agent" является гибкость в выборе поставщика услуг. По мере улучшения моделей или изменения ваших требований, вы можете переключаться между различными сервисами обработки данных, не переписывая логику вашего агента – изменяется только конфигурация клиентской части.

Эта платформа поддерживает следующие сервисы:

| Провайдер | История переписки в чате |
| --- | --- |
| Услуги агента литейного производства | Да |
| Ответы от Azure OpenAI | Да |
| Ответы от OpenAI | Да |
| Функция "Чат" в сервисе Azure OpenAI | Нет |
| Использование функции "Чат" от OpenAI | Нет |
| Anthropic Claude | Нет |
| Amazon Bedrock | Нет |

Этот модуль посвящен поставщику услуг **"Foundry Agent Service"**, который предлагает возможности корпоративного уровня, включая сохранение истории чатов, поддержку инструмента Model Context Protocol (MCP) и интеграцию с сервисами Azure.

# Создайте агента искусственного интеллекта Azure с использованием платформы Microsoft Agent Framework.

Сервис Foundry Agent Service является рекомендуемым поставщиком решений для производственных сред, созданных с использованием платформы Microsoft Agent Framework. Он обеспечивает сохранение истории разговоров на стороне сервера, поддерживает встроенные инструменты, такие как выполнение кода и поиск файлов, а также легко интегрируется с системой управления идентификацией Azure. Эти возможности позволяют вам сосредоточиться на логике работы вашего агента, а не на сложностях его инфраструктуры.

## Настройка агента Foundry.

Создание и взаимодействие с агентом Foundry происходит в соответствии с четкой последовательностью шагов.

### 1. Настройте свой проект в Foundry.

Прежде чем приступить к написанию кода, вам потребуется проект Microsoft Foundry с развернутой моделью. Для подключения к вашему проекту необходимо использовать две следующие данные:

- **URL-адрес проекта:** это адрес вашего проекта Foundry.
- **Название развертывания модели** — это имя развертывания модели, которое вы хотите использовать для вашего агента.

### 2. Настройте аутентификацию.

Фреймворк Agent подключается к вашему проекту Foundry с использованием учетных данных Azure. В большинстве случаев... `DefaultAzureCredential` Система автоматически выбирает необходимые учетные данные в зависимости от вашей среды: Azure CLI во время разработки и управляемые удостоверения в производственной среде. Вам не нужно жестко прописывать строки подключения или ключи API.

### 3. Инициализируйте клиент чата Foundry.

Создайте клиент для взаимодействия с системой Foundry, указав ваши учетные данные, адрес проекта и название модели. Этот клиент служит связующим звеном между вашим приложением и сервисом Foundry Agent. Он обеспечивает аутентификацию, маршрутизацию запросов и управление сеансами на стороне сервера.

### 4. Создайте агента.

Используя клиент чата, создайте агента, предоставив набор инструкций, определяющих его поведение:

- **Инструкции** — системное сообщение, которое определяет роль, цели и ограничения агента.
- **Инструменты** (необязательно) — Пользовательские функции, которые агент может вызывать для выполнения действий или получения информации.

Эта платформа регистрирует все инструменты, которые вы предоставляете, и автоматически создает их схемы, чтобы модель знала, когда и как их использовать.

### 5. Начните сеанс и запустите агент.

Чтобы начать взаимодействие, необходимо открыть сессию через экземпляр агента. Сессия служит контейнером для хранения состояния разговора. Вы отправляете сообщения пользователя в метод выполнения сессии, который обрабатывает запрос, координирует вызовы необходимых инструментов и возвращает ответ модели.

## Многоступенчатые диалоги.
Или: Разговоры, состоящие из нескольких этапов/вопросов и ответов.

Один вызов метода `run` агента обрабатывает один обмен – одно сообщение от пользователя и один ответ. Для поддержания реального диалога необходимо, чтобы агент запоминал, что было сказано в предыдущих репликах. Именно для этого предназначена **сессия**.

Для провайдера Foundry, эти сеансы работы поддерживаются **хранилищем на стороне сервера** — история разговоров хранится в сервисе Foundry Agent, а не в памяти вашего приложения.

- **Сохранение истории:** Поскольку состояние приложения поддерживается на стороне сервера, диалог пользователя может продолжаться между несколькими запросами, даже если ваше приложение перезапускается или масштабируется до нескольких экземпляров.
- **Локальная история:** Для провайдеров, которые не поддерживают хранение истории на стороне сервера, фреймворк сохраняет состояние разговора в памяти внутри объекта сессии. Локальное хранение истории подходит для приложений с коротким жизненным циклом или для stateless-приложений, но данные не сохраняются при перезапуске процесса.

## Ответы без потоковой передачи данных против ответов с потоковой передачей данных.

Фреймворк для агентов поддерживает два режима работы:

- **Непотоковый (синхронный) режим:** метод выполнения ожидает завершения обработки данных агентом и возвращает полный объект ответа. Непотоковый режим – это самый простой вариант, который хорошо подходит, когда нет необходимости отображать результаты по мере их поступления.
- **Потоковая передача (асинхронная)** — метод `run` возвращает поток данных, который вы обрабатываете асинхронно, получая частичные обновления по мере их генерации моделью. Потоковая передача лучше всего подходит для пользовательских интерфейсов, где постепенное отображение результатов улучшает взаимодействие с пользователем.

В обоих случаях ответ демонстрирует... `text` Свойство, которое объединяет весь текстовый вывод агента, что позволяет легко извлечь окончательный ответ, независимо от выбранного режима работы.

# Добавьте инструменты в агента искусственного интеллекта Azure.

Инструменты позволяют вашему агенту выполнять действия: вызывать API, запускать код, искать файлы или взаимодействовать с внешними сервисами. Без инструментов агент может генерировать текст только на основе имеющихся у него знаний. С использованием инструментов он становится способным действовать в реальном мире.

Фреймворк Microsoft Agent поддерживает две основные категории инструментов: **инструменты, предоставляемые сервисом**, которые размещаются и управляются поставщиком услуг, и **индивидуальные инструменты**, которые вы разрабатываете самостоятельно и регистрируете в системе.

## Инструменты, предоставляемые в рамках сервиса.

При использовании провайдера Foundry доступен широкий спектр инструментов, которые не требуют дополнительной настройки. Для их активации необходимо включить их в конфигурацию агента — сам провайдер отвечает за фактическое выполнение этих инструментов.

Наиболее часто используемые инструменты, предоставляемые сервисом, включают в себя:

| Инструмент | Функциональность |
| --- | --- |
| **Интерпретатор кода** | Выполняет код на языке Python в изолированной среде для проведения вычислений и анализа данных. |
| **Поиск по файлам** | Позволяет осуществлять поиск и извлекать информацию из загруженных документов. |
| **Поиск в интернете** | Предоставляет актуальную информацию из сети Интернет. |
| **Инструменты MCP, работающие на стороне сервера:** | Серверы протокола контекста модели (MCP), вызываемые непосредственно средой выполнения провайдера. |
| **Azure AI Search** | Запросы к индексу Azure AI Search выполняются через подключение Foundry. |
| **Наборы инструментов Foundry** | Набор предварительно настроенных и версионированных конфигураций инструментов, используемых в проектах Foundry. |

Примечание.

Некоторые инструменты, включая Azure AI Search, Bing Grounding, SharePoint и другие, находятся в стадии предварительного тестирования или являются экспериментальными. Они доступны для агентов Foundry, но могут иметь ограниченную поддержку у других поставщиков услуг.

## Инструменты для пользовательских функций.

Инструменты с пользовательскими функциями позволяют расширить возможности вашего агента, добавив любую необходимую логику — например, вызов внутренних API, запросы к базам данных, выполнение расчетов или любые другие действия, которые может выполнять функция на языке Python.

Чтобы зарегистрировать функцию как инструмент, необходимо передать ее непосредственно агенту во время его создания. Фреймворк анализирует сигнатуру функции и генерирует схему, которая сообщает модели о том, что делает эта функция, какие параметры она принимает и что возвращает.

Чтобы модель могла надежно вызывать инструменты, ваше функциональное описание должно быть четким и понятным. Фреймворк "Агент" поддерживает два подхода:

- **Аннотации типов с описаниями** — используйте возможности языка Python для этого. `Annotated` тип данных с описанием каждого параметра. Строка документации функции служит описанием инструмента.
- Вот текст для перевода:

**The** `@tool` `decorator` — явно указывайте имя и описание инструмента в качестве аргументов декоратора, что дает вам полный контроль над тем, какую информацию получает модель. Вы также можете предоставить явную схему, используя модель Pydantic, если вам требуется точный контроль над структурой входных данных.

В любом случае, эта система автоматически управляет созданием схемы данных и вызовом инструментов. Когда модель определяет, что необходимо вызвать определенный инструмент, система выполняет соответствующую функцию и возвращает результат модели, прежде чем будет сформирован окончательный ответ.

### Добавление нескольких инструментов.

Вы можете зарегистрировать несколько инструментов, используя один и тот же агент. При создании агента передайте список функций, и модель автоматически выберет наиболее подходящий инструмент для каждой части разговора. Вам не нужно писать никакой логики маршрутизации — фреймворк самостоятельно управляет взаимодействием между инструментами, основываясь на контексте разговора и описаниях инструментов, которые вы предоставляете.

## Одобрение инструмента.

Для сценариев, в которых вызовы инструментов должны требовать проверки человеком перед выполнением, фреймворк Agent поддерживает механизм **подтверждения использования инструмента**. Когда режим подтверждения включен для определенного инструмента, агент приостанавливает работу перед вызовом этой функции и запрашивает подтверждение. Это полезно для действий, которые невозможно отменить, требуют значительных затрат или связаны с конфиденциальными данными. Поведение подтверждения можно настроить для каждого инструмента отдельно. `approval_mode` параметр, указанный в... (или "параметр, относящийся к...") `@tool` дизайнер интерьера.

## Использование агента в качестве инструмента.

Агенты могут быть созданы путем использования одного агента в качестве инструмента для другого. Внутренний агент преобразуется в функцию, которая передается внешнему агенту. Затем внешний агент может делегировать ему выполнение конкретных задач. Это позволяет создавать модульные системы, в которых специализированные агенты занимаются определенными областями, а координационный агент направляет запросы между ними – эта схема рассматривается более подробно в разделе о многоагентных системах.

## Лучшие практики разработки собственных инструментов.

- **Составляйте четкие описания:** способность модели выбирать подходящий инструмент полностью зависит от того, насколько подробными и понятными будут предоставленные вами описания. Указывайте конкретно, что делает функция и в каких случаях ее следует использовать.
- **Описывайте каждый параметр** — давайте подробное описание каждого входного параметра, чтобы модель могла корректно формировать запросы, особенно в тех случаях, когда названия параметров сами по себе не являются достаточно понятными.
- **Возвращайте полезные данные:** инструменты должны выдавать структурированный и понятный результат. Модель использует полученное значение непосредственно при формировании своего ответа.
- **Сосредоточьте инструменты на конкретных задачах:** каждый инструмент должен хорошо выполнять одну определенную функцию. Объединение нескольких задач в рамках одной функции затрудняет правильное использование этого инструмента моделью.
- **Обрабатывайте ошибки корректно:** если инструмент сталкивается с неожиданными входными данными или внешний сервис выходит из строя, возвращайте информативное сообщение об ошибке вместо того, чтобы вызывать исключение, чтобы модель могла предоставить полезную информацию.
