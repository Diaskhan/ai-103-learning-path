# Интегрируйте собственные инструменты в ваш интерфейс обслуживания клиентов.

# Введение.

Сервис Microsoft Foundry Agent предоставляет удобный способ создания агента без необходимости обладать глубокими знаниями в области искусственного интеллекта или машинного обучения. С помощью доступных инструментов вы можете предоставить своему агенту функциональность для выполнения действий от вашего имени.

Сервис AI Agent предоставляет встроенные инструменты для сбора информации и генерации кода, которые обеспечивают вашему агенту мощные возможности. Однако иногда вашему агенту необходимо выполнять определенные задачи или действия, с которыми стандартная модель искусственного интеллекта не сможет справиться самостоятельно. Для выполнения этих задач вы можете предоставить своему агенту *специальный инструмент*, основанный на вашем собственном коде, стороннем сервисе или API.

Представьте, что вы работаете в сфере розничной торговли, и ваша компания испытывает трудности с эффективной обработкой запросов клиентов. Служба поддержки перегружена повторяющимися вопросами, что приводит к задержкам в ответах и снижению удовлетворенности клиентов. Используя Foundry Agent Service с помощью настроенных инструментов, вы можете создать специализированного чат-бота (агента), который будет отвечать на часто задаваемые вопросы. Этот агент может быть оснащен набором специальных инструментов для поиска информации о заказах клиентов, что позволит вашей службе поддержки сосредоточиться на более сложных вопросах.

В этом модуле вы узнаете, как использовать собственные инструменты в сервисе Foundry Agent для повышения производительности, улучшения точности и создания индивидуальных решений, отвечающих конкретным потребностям.

# Зачем использовать специализированные инструменты?

Сервис Microsoft Foundry Agent предоставляет мощную платформу для интеграции пользовательских инструментов, которые повышают производительность и предлагают индивидуальные решения для удовлетворения конкретных бизнес-потребностей. Используя эти инструменты, компании могут добиться большей эффективности и результативности в своей деятельности.

## Зачем использовать специализированные инструменты?

Специализированные инструменты значительно повышают производительность за счет автоматизации повторяющихся задач и оптимизации рабочих процессов, адаптированных к вашим конкретным потребностям. Эти инструменты улучшают точность, обеспечивая точные и стабильные результаты, что снижает вероятность человеческих ошибок. Кроме того, специализированные инструменты предлагают индивидуальные решения, отвечающие конкретным бизнес-задачам, позволяя организациям оптимизировать свои процессы и достигать лучших результатов.

- **Повышенная производительность:** Автоматизируйте повторяющиеся задачи и оптимизируйте рабочие процессы.
- **Повышенная точность:** Обеспечивает точные и стабильные результаты, снижая вероятность человеческих ошибок.
- **Индивидуальные решения:** Удовлетворение конкретных потребностей бизнеса и оптимизация процессов.

Добавление инструментов позволяет предоставить агенту возможность использовать определенные функции, в зависимости от того, как он решит ответить на запрос пользователя. Например, рассмотрим, как пользовательский инструмент для получения данных о погоде из внешней метеорологической службы может быть использован агентом.

![Диаграмма, иллюстрирующая работу агента, использующего специальный инструмент для вызова внешнего метеорологического сервиса.](https://learn.microsoft.com/en-us/training/wwl-data-ai/build-agent-with-custom-tools/media/agent-tool-diagram.png)

На схеме показан процесс выбора агентом использования специализированного инструмента.

1. Пользователь спрашивает у оператора о погодных условиях в горнолыжном курорте.
2. Агент определяет, что у него есть доступ к инструменту, который может использовать API для получения метеорологической информации, и активирует его.
3. Этот инструмент предоставляет прогноз погоды, а агент сообщает эту информацию пользователю.

## Типичные сценарии использования специализированных инструментов в работе агентов.

Встроенные инструменты в сервисе Foundry Agent позволяют пользователям расширять возможности ИИ-агентов, адаптируя их к конкретным потребностям бизнеса. Вот несколько примеров использования этих инструментов, демонстрирующих их универсальность и влияние:

### Автоматизация поддержки клиентов.

- **Сценарий:** Розничная компания интегрирует разработанный специально инструмент, который связывает службу искусственного интеллекта Azure с их системой управления взаимоотношениями с клиентами (CRM).
- Функциональность: Искусственный интеллект может получать доступ к истории заказов клиентов, обрабатывать запросы на возврат средств и предоставлять актуальную информацию о статусе доставки в режиме реального времени.
- **Результат:** Более быстрое решение вопросов клиентов, снижение нагрузки на отделы поддержки и повышение уровня удовлетворенности клиентов.

### Управление запасами.

- **Сценарий:** Производственная компания разрабатывает специальный инструмент для интеграции искусственного интеллекта с их системой управления запасами.
- Функциональность: Искусственный интеллект может проверять уровень запасов, прогнозировать необходимость пополнения запасов на основе исторических данных и автоматически оформлять заказы у поставщиков.
- **Результат:** Оптимизация процессов управления запасами и повышение эффективности работы цепочки поставок.

### Запись на прием к врачу.

- **Сценарий:** Медицинское учреждение интегрирует разработанный специально для них инструмент планирования с искусственным интеллектом.
- Функциональность: Искусственный интеллект может получать доступ к медицинским записям пациентов, предлагать доступные даты и время для записи на прием и отправлять напоминания пациентам.
- **Результат:** Снижение административной нагрузки, улучшение качества обслуживания пациентов и более эффективное использование ресурсов.

### Техническая поддержка пользователей (компьютерной техники).
Или: Служба технической поддержки.
Или: Поддержка пользователей в вопросах информационных технологий.
(Выбор наиболее подходящего варианта зависит от контекста.)

- **Сценарий:** Отдел информационных технологий разрабатывает собственное программное обеспечение для интеграции искусственного интеллекта с системами обработки запросов и базы знаний, используемыми в компании.
- Функциональность: Искусственный интеллект может решать распространенные технические проблемы, передавать сложные вопросы специалистам и отслеживать статус запросов.
- **Результат:** Более быстрое устранение проблем, сокращение времени простоя и повышение производительности сотрудников.

### Электронное обучение и повышение квалификации.

- **Сценарий:** Образовательное учреждение разрабатывает собственное программное обеспечение для интеграции искусственного интеллекта с их системой управления обучением (LMS).
- Функциональность: Искусственный интеллект может рекомендовать курсы, отслеживать успеваемость студентов и отвечать на вопросы о содержании курсов.
- **Результат:** Улучшение качества обучения, повышение вовлеченности студентов и оптимизация административных процессов.

Эти примеры демонстрируют, как специализированные инструменты, доступные в рамках сервиса Foundry Agent, могут быть использованы в различных отраслях для решения уникальных задач, повышения эффективности и создания ценности.

# Варианты реализации пользовательских инструментов.

Сервис Microsoft Foundry Agent предоставляет различные инструменты, разработанные по индивидуальному заказу, которые расширяют возможности и повышают эффективность ваших ИИ-агентов. Эти инструменты обеспечивают масштабируемую совместимость с различными приложениями, что упрощает интеграцию с существующей инфраструктурой или веб-сервисами.

## В службе Microsoft Foundry Agent доступны дополнительные возможности настройки инструментов.

Сервис Foundry Agent предоставляет различные варианты инструментов, включая инструменты, соответствующие спецификации OpenAPI, функции Azure и вызовы функций. Эти инструменты обеспечивают бесперебойную интеграцию с внешними API, приложениями, работающими на основе событий, и пользовательскими функциями.

- **Пользовательская функция:** Функция вызова позволяет вам описывать структуру пользовательских функций для агента и возвращать функции, которые необходимо вызвать, вместе с их аргументами. Агент может динамически определять подходящие функции на основе их описаний. Эта функция полезна для интеграции пользовательской логики и рабочих процессов, реализованных на различных языках программирования, в ваши AI-агенты.
- **Azure Functions:** Azure Functions позволяют создавать интеллектуальные приложения, работающие по принципу обработки событий, с минимальными затратами ресурсов. Они поддерживают триггеры и привязки, которые упрощают взаимодействие ваших AI-агентов с внешними системами и сервисами. Триггеры определяют, когда функция должна быть запущена, а привязки обеспечивают удобное подключение к источникам входных или выходных данных.
- **Инструменты для работы со спецификациями OpenAPI:** Эти инструменты позволяют подключить вашего агента Azure AI к внешнему API с использованием спецификации OpenAPI 3.0. Это обеспечивает стандартизированную, автоматизированную и масштабируемую интеграцию с API, что расширяет возможности вашего агента. Спецификации OpenAPI описывают HTTP-API, позволяя пользователям понимать принцип работы API, генерировать клиентский код, создавать тесты и применять стандарты проектирования.
- **Azure Logic Apps:** Эта функция предлагает решения с минимальным или полным отсутствием необходимости в программировании для добавления рабочих процессов и интеграции приложений, данных и сервисов с помощью платформы Logic Apps, требующей минимального количества кода.

Эта гибкость, позволяющая интегрировать пользовательские функции различными способами, открывает широкие возможности для расширения функциональности ваших агентов сервиса Foundry Agent.

# Как интегрировать собственные инструменты.

Специальные инструменты для агента можно определить несколькими способами, в зависимости от того, что лучше всего подходит для вашей конкретной ситуации. Возможно, вы обнаружите, что ваша компания уже использует Azure Functions, которые ваш агент может использовать, или общедоступная спецификация OpenAPI предоставляет вашему агенту необходимые функции.

## Вызов функций.

Функции вызова позволяют агентам динамически выполнять предопределенные функции на основе пользовательского ввода. Эта функция идеально подходит для ситуаций, когда агентам необходимо выполнять определенные задачи, такие как получение данных или обработка запросов пользователей, и это можно реализовать в коде непосредственно внутри агента. Ваша функция может обращаться к другим API для получения дополнительной информации или запуска программ.

### Определение и использование функции.

Начните с определения функции, которую агент сможет вызывать. Например, вот пример фиктивной функции для отслеживания снегопада:

```
import json

def recent_snowfall(location: str) -> str:
    """
    Fetches recent snowfall totals for a given location.
    :param location: The city name.
    :return: Snowfall details as a JSON string.
    """
    mock_snow_data = {"Seattle": "0 inches", "Denver": "2 inches"}
    snow = mock_snow_data.get(location, "Data not available.")
    return json.dumps({"location": location, "snowfall": snow})
```

Зарегистрируйте функцию у своего агента, используя пакет разработки программного обеспечения (SDK) Azure AI:

```
# Define a function tool for the model to use
function_tool = FunctionTool(
    name="recent_snowfall",
    parameters={
        "type": "object",
        "properties": {
            "location": {"type": "string", "description": "The city name to check snowfall for."},
        },
        "required": ["location"],
        "additionalProperties": False
    },
    description="Get recent snowfall totals for a given location.",
    strict=True,
)

# Add the function tool to a list of tools for the agent
tools: list[Tool] = [function_tool]

# Create your agent with the toolset
agent = project_client.agents.create_version(
    name="snowfall-agent",
    definition=PromptAgentDefinition(
        model="gpt-4.1",
        instructions="You are a weather assistant tracking snowfall. Use the provided functions to answer questions.",
        tools=tools,
    )
)
```

Теперь агент может динамически вызывать функцию *recent_snowfall*, когда определяет, что запрос требует информации, которую можно получить с помощью этой функции.

## Azure Functions (или "Функции Azure") - это бессерверная вычислительная платформа от Microsoft Azure.

Azure Functions предоставляет возможности серверного вычисления для обработки данных в реальном времени. Эта интеграция идеально подходит для рабочих процессов, основанных на событиях, позволяя системам реагировать на различные триггеры, такие как HTTP-запросы или сообщения из очередей.

### Пример: Использование Azure Functions с триггером на основе очереди.

---

You are a professional English (en) to Russian (ru) translator. Your goal is to accurately convey the meaning and nuances of the original English text while adhering to Russian grammar, vocabulary, и cultural sensitivities.
Produce only the Russian translation, without any additional explanations or commentary. Please translate the following English text into Russian:

Example: The company's profits increased significantly last year.

Во-первых, разработайте и разверните свою функцию Azure. В этом примере представим, что у нас есть функция в нашей подписке Azure, которая предназначена для получения данных об уровне снегопада для определенного местоположения.

После того как ваша функция Azure будет настроена, добавьте ее в определение агента в качестве инструмента, использующего функции Azure.

```
tool = AzureFunctionTool(
    azure_function=AzureFunctionDefinition(
        input_binding=AzureFunctionBinding(
            storage_queue=AzureFunctionStorageQueue(
                queue_name="STORAGE_INPUT_QUEUE_NAME",
                queue_service_endpoint="STORAGE_QUEUE_SERVICE_ENDPOINT",
            )
        ),
        output_binding=AzureFunctionBinding(
            storage_queue=AzureFunctionStorageQueue(
                queue_name="STORAGE_OUTPUT_QUEUE_NAME",
                queue_service_endpoint="STORAGE_QUEUE_SERVICE_ENDPOINT",
            )
        ),
        function=AzureFunctionDefinitionFunction(
            name="queue_trigger",
            description="Get weather for a given location",
            parameters={
                "type": "object",
                "properties": {"location": {"type": "string", "description": "location to determine weather for"}},
            },
        ),
    )
)

agent = project_client.agents.create_version(
    agent_name="MyAgent",
    definition=PromptAgentDefinition(
        model="gpt-4.1",
        instructions="You are a helpful weather assistant. Use the provided Azure Function to get weather information for a location when needed.",
        tools=[tool],
    ),
)
```

Теперь агент может отправлять запросы к функции Azure через очередь хранения и обрабатывать полученные результаты.

## Спецификация OpenAPI.

Инструменты, определенные в спецификации OpenAPI, позволяют агентам взаимодействовать с внешними API, используя стандартизированные параметры. Такой подход упрощает интеграцию с API и обеспечивает совместимость с различными сервисами. Сервис Foundry Agent использует инструменты, соответствующие спецификации OpenAPI 3.0.

Совет.

В настоящее время инструменты OpenAPI 3.0 поддерживают три типа аутентификации: *анонимная аутентификация*, *аутентификация по ключу API* и *аутентификация с использованием управляемой учетной записи*.

### Пример: Использование спецификации OpenAPI.

---

You are a professional English (en) to Russian (ru) translator. Your goal is to accurately convey the meaning and nuances of the original English text while adhering to Russian grammar, vocabulary, and cultural sensitivities.
Produce only the Russian translation, without any additional explanations or commentary. Please translate the following English text into Russian:

Example: The company's profits increased significantly last year.

Во-первых, создайте файл в формате JSON (в данном примере он называется *weather_openapi.json*), который будет описывать API.

```
{
  "openapi": "3.1.0",
  "info": {
    "title": "get weather data",
    "description": "Retrieves current weather data for a location based on wttr.in.",
    "version": "v1.0.0"
  },
  "servers": [
    {
      "url": "https://wttr.in"
    }
  ],
  "auth": [],
  "paths": {
    "/{location}": {
      "get": {
        "description": "Get weather information for a specific location",
        "operationId": "GetCurrentWeather",
        "parameters": [
          {
            "name": "location",
            "in": "path",
            "description": "City or location to retrieve the weather for",
            "required": true,
            "schema": {
              "type": "string"
            }
          },
          {
          "name": "format",
          "in": "query",
          "description": "Always use j1 value for this parameter",
          "required": true,
          "schema": {
            "type": "string",
            "default": "j1"
          }
        }
        ],
        "responses": {
          "200": {
            "description": "Successful response",
            "content": {
              "text/plain": {
                "schema": {
                  "type": "string"
                }
              }
            }
          },
          "404": {
            "description": "Location not found"
          }
        },
        "deprecated": false
      }
    }
  },
  "components": {
    "schemes": {}
  }
}
```

Затем зарегистрируйте инструмент OpenAPI в определении агента:

```
from azure.ai.projects.models import OpenApiTool, OpenApiAnonymousAuthDetails

with open(weather_asset_file_path, "r") as f:
      openapi_weather = cast(dict[str, Any], jsonref.loads(f.read()))

tool = OpenApiTool(
    openapi=OpenApiFunctionDefinition(
        name="get_weather",
        spec=openapi_weather,
        description="Retrieve weather information for a location.",
        auth=OpenApiAnonymousAuthDetails(),
    )
)

agent = project_client.agents.create_version(
    agent_name="openapi-agent",
    definition=PromptAgentDefinition(
        model="gpt-4.1",
        instructions="You are a weather assistant. Use the API to fetch weather data.",
        tools=[openapi_tool],
    ),
)
```

Теперь агент может использовать инструмент OpenAPI для динамической загрузки данных о погоде.

Примечание.

Одной из концепций, связанных с агентами и пользовательскими инструментами, которая часто вызывает затруднения у разработчиков, является *декларативный* характер решения. Вам не нужно писать код, который явно *вызывает* функции ваших пользовательских инструментов – сам агент решает, когда вызывать эти функции, основываясь на сообщениях в запросах. Предоставляя агенту функции с понятными названиями и хорошо документированными параметрами, агент может самостоятельно "понять", когда и как вызвать эту функцию!

Используя один из доступных инструментов или их комбинацию, вы можете создавать мощные, гибкие и интеллектуальные приложения с помощью сервиса Foundry Agent Service. Эти интеграции обеспечивают бесперебойное взаимодействие с внешними системами, обработку данных в реальном времени и масштабируемые рабочие процессы, что упрощает создание индивидуальных решений, адаптированных к вашим потребностям.
