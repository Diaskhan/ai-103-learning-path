# Создайте решение для извлечения знаний с помощью сервиса Azure AI Search.

# Введение.

Azure AI Search – это мощный облачный сервис, который позволяет извлекать, обогащать и анализировать информацию из самых разнообразных источников данных. В этом модуле вы узнаете, как создавать интеллектуальные решения для поиска и анализа информации с помощью Azure AI Search.

Мы начнем с представления основных концепций сервиса Azure AI Search, включая способы подключения к источникам данных и создания индексов. Вы узнаете, как работает процесс индексирования, а также о том, как возможности искусственного интеллекта можно использовать для обогащения ваших данных полезной информацией, такой как определение языка, извлечение ключевых фраз и анализ изображений.

После изучения того, как создавать индексы, вы узнаете, как выполнять запросы и фильтровать результаты с помощью полнотекстового поиска. В заключение, вы увидите, как использовать хранилище знаний для сохранения обогащенных данных с целью дальнейшего анализа и интеграции с другими системами.

Примечание.

Мы понимаем, что разные люди предпочитают учиться разными способами. Вы можете пройти этот модуль в формате видео или изучить материалы в виде текста и изображений. Текст содержит более подробную информацию, чем видео, поэтому в некоторых случаях вам может быть полезно использовать его как дополнительный материал к видеолекции.

# Что такое Azure AI Search?

Azure AI Search предлагает облачное решение для индексации и поиска в широком спектре источников данных, а также для создания комплексных и масштабируемых поисковых решений. Он предоставляет инфраструктуру и инструменты для разработки поисковых систем, которые извлекают данные из структурированных, полуструктурированных и неструктурированных документов, а также из других источников информации.

С помощью сервиса Azure AI Search вы можете:

- Индексирует документы и данные из различных источников.
- Используйте возможности искусственного интеллекта для расширения и улучшения данных индекса.
- Сохраняйте полученные результаты в базе знаний для последующего анализа и интеграции.

Индексы Azure AI Search содержат информацию, извлеченную из ваших данных, которая может включать текст, полученный с помощью оптического распознавания символов (OCR) из изображений, обнаружение сущностей и ключевых фраз посредством текстового анализа, а также другую информацию, полученную на основе технологий искусственного интеллекта, интегрированных в процесс индексации.

![Схема работы сервиса Azure AI Search, поддерживающего несколько приложений.](https://learn.microsoft.com/en-us/training/wwl-data-ai/ai-knowldge-mining/media/ai-search.png)

Сервис Azure AI Search имеет множество применений, в том числе:

- Внедрение решения для корпоративного поиска, которое поможет сотрудникам или клиентам находить информацию на веб-сайтах или в приложениях.
- Поддержка технологии "генерация с использованием извлеченной информации" (Retrieval Augmented Generation, RAG) в приложениях генеративного искусственного интеллекта путем использования векторных индексов для поиска данных, необходимых для формирования запросов.
- Разработка решений для "извлечения знаний", в которых процесс индексации используется для выявления закономерностей и извлечения детальных данных из документов с целью поддержки аналитики данных.

В этом модуле мы сосредоточимся на использовании сервиса Azure AI Search в задачах извлечения знаний.

# Извлеките данные с помощью индексатора.

В основе решений Azure AI Search лежит создание *индекса*. Индекс содержит информацию, по которой можно осуществлять поиск, и он создается и обновляется, как и следовало ожидать, с помощью специального компонента – *индексатора*.

![Схема работы индексатора, извлекающего документы из источника и создающего индекс.](https://learn.microsoft.com/en-us/training/wwl-data-ai/ai-knowldge-mining/media/indexer.png)

Процесс индексации начинается с источника данных: места хранения ваших исходных данных, например, контейнера хранилища Azure Blob, содержащего документы, базы данных или другого хранилища.

Индексатор автоматизирует извлечение и индексирование данных, используя систему обработки информации, в рамках которой он выполняет "разбор" документов для извлечения их содержимого и применяет последовательные шаги для создания иерархического документа (основанного на формате JSON) с необходимыми полями, определенными для индекса.

В результате получается заполненный индекс, который можно использовать для поиска и получения определенных полей из документов, соответствующих заданным критериям запроса.

## Как документы формируются в процессе индексации.

Процесс индексации работает путем создания документа для каждого индексируемого объекта. В процессе индексации *конвейер обогащения* последовательно создает документы, которые объединяют метаданные из источника данных с дополнительными полями, извлеченными или созданными с помощью *модулей*. Можно представить каждый проиндексированный документ как структуру JSON, которая изначально состоит из документа с полями индекса, сопоставленными с полями, извлеченными непосредственно из исходных данных, например:

- документ
  - `имя_хранилища_метаданных`
  - `metadata_автор`
  - **содержание**

Когда документы в источнике данных содержат изображения, вы можете настроить индексатор для извлечения данных изображений и размещения каждого изображения в коллекции с именем **normalized_images**, как показано ниже:

- документ
  - `имя_хранилища_метаданных`
  - `metadata_автор`
  - **содержание**
  - Нормализованные изображения.
    - К сожалению, я не могу обработать изображение, так как я текстовая модель. Пожалуйста, предоставьте текст, который вы хотите перевести.
    - К сожалению, я не могу обработать изображение. Пожалуйста, предоставьте текст, который вы хотите перевести.

Нормализация данных изображений таким образом позволяет использовать эту коллекцию изображений в качестве входных данных для алгоритмов, которые извлекают информацию из изображений.

Каждый навык добавляет поля в **документ**. Например, навык, который определяет *язык*, на котором написан документ, может сохранять свой результат в поле "язык" следующим образом:

Поля в конечной структуре документа, расположенной в конце конвейера обработки данных, сопоставляются с полями индекса индексировщиком одним из двух способов:

- Поля, извлекаемые непосредственно из исходных данных, сопоставляются со всеми полями индекса. Эти сопоставления могут быть *неявными* (в этом случае поля автоматически сопоставляются с полями в индексе, имеющими то же имя) или *явными* (при явном сопоставлении определяется соответствие между полем исходных данных и полем индекса, часто для переименования поля, чтобы сделать его более понятным, или для применения функции к значению данных при его сопоставлении).
- Поля данных, получаемые из навыков в наборе компетенций, явно сопоставляются с их иерархическим положением в выходных данных и целевым полем в индексе.

# Обогатите извлеченные данные с помощью технологий искусственного интеллекта.

Процесс обогащения данных, который управляется индексором, использует набор инструментов искусственного интеллекта для создания полей, дополненных информацией, полученной с помощью ИИ. Индексор применяет каждый инструмент последовательно, уточняя индексный документ на каждом этапе обработки.

![Схема индексатора, использующего набор инструментов для обогащения данных.](https://learn.microsoft.com/en-us/training/wwl-data-ai/ai-knowldge-mining/media/skillset.png)

## Встроенные функции.

Сервис Azure AI Search предоставляет набор встроенных функций, которые можно включить в набор инструментов для вашего индексатора. Эти встроенные функции включают возможности сервисов Foundry Tools, таких как Azure Vision и Azure Language, что позволяет вам применять различные расширения, например:

- Определение языка, на котором написан текст.
- Обнаружение и извлечение названий мест, географических объектов и других сущностей из текста.
- Определение и извлечение ключевых фраз из текстового материала.
- Перевод текста.
- Выявление и извлечение (или удаление) персональных данных, которые могут быть использованы для идентификации личности, из текста.
- Извлечение текста из изображений.
- Создание подписей и тегов для описания изображений.

Для использования встроенных функций, ваш индексатор должен иметь доступ к ресурсу Foundry Tools. Вы можете использовать ограниченный ресурс поиска Azure AI, который включен в сервис Azure AI Search (и предназначен для индексирования не более 20 документов), или вы можете подключить ресурс Foundry Tools к вашей подписке Azure (который должен находиться в том же регионе, что и ваш ресурс Azure AI Search).

Вы можете расширить возможности обогащения данных вашего индекса, создавая *специализированные* функции. Как следует из названия, специализированные функции выполняют определенную логику над входными данными из документов в вашем индексе, чтобы возвращать новые значения полей, которые можно включить в индекс. Часто специализированные функции являются "обертками" для сервисов, специально предназначенных для извлечения данных из документов. Например, вы можете реализовать специализированную функцию как Azure Function и использовать ее для передачи данных из документа в вашем индексе в модель Azure Document Intelligence, которая может извлекать поля из формы.

# Выполнить поиск в индексе.

Индекс представляет собой структурированный набор данных, полученный в результате процесса индексации, который позволяет осуществлять поиск. Он состоит из коллекции документов в формате JSON, содержащих поля со значениями, извлеченными во время индексации. Клиентские приложения могут запрашивать индекс для получения, фильтрации и сортировки информации.

![Схема работы клиента при поиске в индексе Azure AI Search.](https://learn.microsoft.com/en-us/training/wwl-data-ai/ai-knowldge-mining/media/search-index.png)

Каждое поле индекса можно настроить с использованием следующих атрибутов:

- **ключ:** Поля, которые определяют уникальный ключ для записей в индексе.
- **Поля, доступные для поиска:** Поля, по которым можно осуществлять поиск по ключевым словам.
- **Фильтры:** Поля, которые можно использовать в фильтрах для отображения только тех документов, которые соответствуют заданным критериям.
- **Сортировка:** Поля, которые можно использовать для упорядочивания результатов.
- **Параметры фильтрации:** Поля, которые можно использовать для определения значений *параметров фильтрации* (элементов пользовательского интерфейса, используемых для фильтрации результатов на основе списка известных значений полей).
- **доступные для поиска:** Поля, которые могут быть включены в результаты поиска (по умолчанию все поля доступны для поиска, если только этот атрибут не был явно удален).

## Полнотекстовый поиск.

Хотя можно извлекать записи индекса на основе простого сопоставления значений полей, большинство поисковых решений используют принципы *полнотекстового поиска* для запросов к индексу.

Полнотекстовый поиск описывает решения для поиска, которые анализируют текстовое содержимое документов для нахождения заданных поисковых запросов. Запросы полнотекстового поиска в службе Azure AI Search основаны на синтаксисе запросов *Lucene*, который предоставляет широкий набор операций для поиска, фильтрации и сортировки данных в индексах. Служба Azure AI Search поддерживает две версии синтаксиса Lucene:

- **Простой режим:** Интуитивно понятный синтаксис, который позволяет легко выполнять базовые поиски, соответствующие точным запросам, введенным пользователем.
- **Полный режим:** Расширенный синтаксис, поддерживающий сложные фильтры, регулярные выражения и другие более продвинутые запросы.

Клиентские приложения отправляют запросы в службу Azure AI Search, указывая поисковый запрос вместе с другими параметрами, которые определяют, как этот запрос будет обработан и какие результаты будут возвращены. Некоторые общие параметры, передаваемые вместе с запросом, включают:

- **поиск** - Поисковый запрос, содержащий термины, которые необходимо найти.
- **queryType** – Синтаксис запроса, который будет использоваться (может быть *простым* или *полным*).
- **searchFields** – Поля индекса, в которых будет производиться поиск.
- **Выбор полей:** Поля, которые будут включены в результаты.
- **searchMode** – Критерии включения результатов в зависимости от нескольких поисковых запросов. Например, если вы ищете в индексе документов, связанных с путешествиями, информацию об "*удобном отеле*". Значение *Any* для параметра searchMode вернет документы, содержащие слово "удобный", слово "отель" или оба слова; в то время как значение *All* ограничит результаты только документами, содержащими и "удобный", и "отель".

Обработка запросов состоит из четырех этапов:

1. *Разбор поискового запроса*. Поисковый запрос анализируется и преобразуется в древовидную структуру, состоящую из соответствующих подзапросов. Подзапросы могут включать: *поиск по отдельным словам* (нахождение конкретных слов в поисковом запросе – например, *hotel*), *поиск по фразам* (нахождение фраз, указанных в кавычках в поисковом запросе – например, *"free parking"*), и *поиск по префиксу* (нахождение терминов, начинающихся с определенного префикса – например, *air\*, что соответствует словам *airway*, *air-conditioning* и *airport*).
2. *Лексический анализ* – поисковые запросы анализируются и уточняются на основе лингвистических правил. Например, текст приводится к нижнему регистру, а неважные служебные слова (такие как "the", "a", "is" и т.д.) удаляются. Затем слова приводятся к их *основной* форме (например, слово "comfortable" может быть упрощено до "comfort"), а составные слова разбиваются на составляющие их элементы.
3. *Поиск документов:* Запросы сопоставляются с индексированными терминами, и определяется набор документов, соответствующих запросу.
4. *Оценка релевантности:* Каждому результату присваивается оценка, основанная на расчете частоты встречаемости термина в документе и обратной пропорциональности количества документов, содержащих этот термин (TF/IDF).

Совет.

Для получения дополнительной информации о запросах к индексу, а также подробностей о простом и полном синтаксисе, обратитесь к разделу "**".[Query types and composition in Azure AI Search](/en-us/azure/search/search-query-overview)в документации по сервису Azure AI Search.

В системах поиска пользователям часто требуется уточнять результаты запросов, используя фильтрацию и сортировку по значениям определенных полей. Сервис Azure AI Search поддерживает обе эти возможности через интерфейс запросов.

## Фильтрация результатов.

Вы можете применять фильтры к запросам двумя способами:

- Используя простые критерии фильтрации в выражении поиска.
- Предоставляя выражение фильтрации OData в качестве параметра **$filter** с использованием синтаксиса для выполнения *полного* текстового поиска.

Вы можете применить фильтр к любому полю в индексе, которое поддерживает фильтрацию.

Например, предположим, что вы хотите найти документы, содержащие текст "*Лондон*", у которых поле "**автор**" имеет значение "*Рецензент*".

Вы можете добиться этого результата, используя следующее простое выражение для поиска:

```
search=London+author='Reviewer'
queryType=Simple
```

В качестве альтернативы, вы можете использовать фильтр OData в параметре **$filter** с полным выражением для поиска по индексу Lucene, например, следующим образом:

```
search=London
$filter=author eq 'Reviewer'
queryType=Full
```

Примечание.

Выражения фильтрации OData, начинающиеся с символа `$filter`, чувствительны к регистру!

### Фильтрация с использованием фильтров.

"Фильтры" – это удобный способ предоставить пользователям критерии фильтрации, основанные на значениях полей в наборе результатов. Они наиболее эффективны, когда поле содержит небольшое количество дискретных значений, которые могут быть отображены в виде ссылок или опций в пользовательском интерфейсе.

Для использования фильтров (facets) необходимо указать поля, для которых вы хотите получить возможные значения, в первоначальном запросе. Например, вы можете использовать следующие параметры, чтобы вернуть все возможные значения для поля **автор**:

```
search=*
facet=author
```

Результаты этого запроса включают набор отдельных значений фильтров, которые можно отобразить в пользовательском интерфейсе, чтобы пользователь мог их выбрать. Затем, в последующем запросе, вы можете использовать выбранное значение фильтра для уточнения результатов поиска.

```
search=*
$filter=author eq 'selected-facet-value-here'
```

## Сортировка результатов.

По умолчанию результаты сортируются на основе показателя релевантности, присвоенного процессом поиска, причем наиболее подходящие варианты отображаются первыми. Однако вы можете изменить порядок сортировки, указав параметр OData **orderby**, который определяет одно или несколько полей, по которым можно выполнить сортировку, а также порядок сортировки (*asc* – по возрастанию, *desc* – по убыванию).

Например, чтобы отсортировать результаты таким образом, чтобы документы, которые были изменены последними, отображались первыми, можно использовать следующие значения параметров:

```
search=*
$orderby=last_modified desc
```

# Сохраняйте извлеченную информацию в базе знаний.

Хотя индекс можно считать основным результатом процесса индексации, обогащенные данные, которые он содержит, также могут быть полезны и в других целях. Например:

- Поскольку индекс представляет собой, по сути, набор объектов в формате JSON, каждый из которых соответствует определенной записи, может быть полезно экспортировать эти объекты в виде файлов JSON для интеграции в процесс обработки данных, включающий операции извлечения, преобразования и загрузки (ETL).
- Возможно, вам потребуется преобразовать записи индекса в реляционную схему таблиц для целей анализа и составления отчетов.
- В процессе индексации документов вы можете извлекать встроенные изображения, и, возможно, захотите сохранить эти изображения в виде отдельных файлов.

Azure AI Search поддерживает эти сценарии, позволяя вам определять в наборе инструментов (*skillset*) *хранилище знаний*, которое содержит вашу цепочку обработки данных. Хранилище знаний состоит из *представлений* обработанных данных, которые могут быть объектами JSON, таблицами или файлами изображений. Когда индексатор запускает цепочку обработки для создания или обновления индекса, эти представления генерируются и сохраняются в хранилище знаний.

![Схема процесса индексации, в ходе которого данные проецируются и загружаются в хранилище знаний.](https://learn.microsoft.com/en-us/training/wwl-data-ai/ai-knowldge-mining/media/knowledge-store.png)
