# Разрабатывайте приложения на основе генеративного искусственного интеллекта, использующие различные инструменты.

# Введение.

Модели генеративного искусственного интеллекта обладают мощными возможностями в понимании и создании текста, но их работа ограничена определенным объемом знаний. Они могут анализировать только информацию, содержащуюся в данных, на которых они были обучены. Интегрируя **инструменты** в процессы взаимодействия с моделями генеративного ИИ, вы открываете возможности, которые значительно превосходят то, что может сделать модель сама по себе.

Примечание.

Использование *инструментов* в запросах к моделям генеративного искусственного интеллекта не следует путать с...[Foundry Tools](/en-us/azure/ai-services/reference/sdk-package-resources?azure-portal=true)*; это API искусственного интеллекта Azure, которые вы можете использовать в своих приложениях и системах.

## Почему инструменты имеют значение.

Инструменты помогают преодолеть разрыв между логикой искусственного интеллекта и реальными действиями. Они позволяют вашим приложениям, использующим генеративный ИИ, выполнять следующие задачи:

- **Получайте информацию в режиме реального времени:** Получайте актуальные данные, прогнозы погоды, котировки акций или ответы от API, которые не были включены в обучающие данные модели.
- **Выполняйте действия:** выполняйте задачи, такие как отправка электронных писем, создание записей в базе данных или запуск рабочих процессов на основе решений, принятых с помощью искусственного интеллекта.
- **Основа ответов на фактах:** Получение конкретной и достоверной информации для уменьшения количества неверных сведений и повышения точности.
- **Расширение функциональности:** Легко интегрируйте систему с вашими существующими системами, базами данных и бизнес-логикой.
- **Создавайте интеллектуальные рабочие процессы:** Объединяйте несколько операций в цепочку, чтобы искусственный интеллект мог координировать сложные, многоэтапные процессы.

Без использования инструментов генеративный искусственный интеллект работает изолированно. С использованием инструментов он превращается в интеллектуального помощника, который может наблюдать за окружающим миром, анализировать информацию и действовать на ее основе.

В этом модуле мы сосредоточимся на том, как указывать инструменты в запросах, которые клиентское приложение отправляет модели. В подобных решениях конфигурация инструментов управляется самим клиентским приложением, что по сути означает создание специализированного помощника на основе генеративного искусственного интеллекта непосредственно внутри логики приложения. Изучение того, как использовать инструменты по требованию с моделью генеративного искусственного интеллекта, является важным первым шагом в освоении разработки решений *на базе агентного искусственного интеллекта*, в которых модель, инструкции и инструменты объединяются и сохраняются в так называемом *агенте*.

Совет.

Вы можете узнать больше о том, как использовать SDK для агентов Microsoft Foundry, чтобы создавать агентов с сохраняемыми настройками, в... [Develop AI agents on Azure](/en-us/training/paths/develop-ai-agents-azure/).

Примечание.

Мы понимаем, что разные люди предпочитают учиться разными способами. Вы можете пройти этот модуль в формате видео или изучить материалы в виде текста и изображений. Текст содержит более подробную информацию, чем видео, поэтому в некоторых случаях вам может быть полезно использовать его как дополнительный материал к видеолекции.

# Что такое инструменты?

Модели Microsoft Foundry включают в себя модели, способные использовать инструменты для поиска информации или выполнения задач. Вы можете настроить использование инструментов в этих моделях, указав, какие именно инструменты вы хотите, чтобы модель использовала, при отправке запросов через API *Responses* от OpenAI.

![Схема приложения, которое настраивает модель для использования инструментов.](https://learn.microsoft.com/en-us/training/wwl-data-ai/use-generative-ai-tools/media/tools.png)

При разработке приложения с использованием генеративного искусственного интеллекта в Microsoft Foundry вы можете искать модели с поддержкой вызова инструментов и развернуть их. Затем вы можете разрабатывать клиентские приложения, которые используют API OpenAI Responses для отправки запросов к развернутой модели, указывая инструменты, которые модель может использовать.

Примечание.

По умолчанию модель самостоятельно определяет, когда и какой инструмент использовать, основываясь на полученном запросе. Вы можете настроить правила выбора инструментов и использовать параметр "Инструкции" (системный запрос), чтобы направлять этот выбор.

Некоторые из наиболее часто используемых инструментов, доступных в API "Ответы", включают в себя:

- **code_interpreter:** Среда выполнения на языке Python, в которой модель может генерировать и запускать код.
- **web_search:** Инструмент, который позволяет модели искать общую информацию в интернете, что дает ей возможность основывать свои ответы на более актуальных данных, чем те, на которых она была обучена.
- **file_search:** Инструмент, который позволяет модели искать конкретные файлы, которые вы загружаете в специальный индекс векторного поиска, что дает ей возможность основывать свои ответы на конкретных знаниях.
- **Функция:** Инструмент, который позволяет модели вызывать пользовательские функции, определенные в коде вашего приложения.

Мы рассмотрим эти инструменты в этом модуле.

Совет.

Это лишь *некоторые* из доступных инструментов; разработка инструментов для решений на основе автономного искусственного интеллекта – это развивающаяся область. Чтобы узнать больше об инструментах, поддерживаемых в API ответа OpenAI, обратитесь к [ссылке/разделу]. [OpenAI developer guide](https://developers.openai.com/api/docs/guides/tools?azure-portal=true)

## Указание инструментов в API "Ответы".

Вы можете указать один или несколько инструментов в запросе к... `responses.create()` метод, используемый при генерации ответа моделью. Следующий пример псевдокода на языке Python показывает, где указывается список доступных инструментов:

```
from openai import OpenAI

client = OpenAI(
    base_url={openai_endpoint},
    api_key={auth_key_or_token}
)

response = client.responses.create(
    model={model_deployment},
    instructions="You are a helpful AI assistant.",
    input="Find me some information about vintage computers.",
    # Specify available tools as a JSON list
    tools=[
        { 
            # A tool definition
            "type": "{tool_type}",
            "{tool-specific-setting}": "{value}",
                ...
        },
        { 
            # Another tool definition
            "type": "{another_tool_type}",
            "{tool-specific-setting}": "{value}",
                ...
        }
    ]
)
print(response.output_text)
```

Совет.

Чтобы узнать больше об использовании API "Ответы" для отправки запроса к модели в платформе Microsoft Foundry, обратитесь к [ссылке/документации]. [Develop a generative AI chat app with Microsoft Foundry](/en-us/training/modules/foundry-sdk?azure-portal=true) модуль.

# Используйте инструмент "code_interpreter".

Инструмент *code_interpreter* предоставляет вашей модели среду выполнения на языке Python, в которой она может генерировать и запускать код на этом языке.

## Что такое инструмент "code_interpreter"?

Инструмент "code_interpreter" позволяет моделям генеративного искусственного интеллекта динамически создавать и запускать код на языке Python во время разговора. Вместо того чтобы просто обсуждать код или алгоритмы, модель может проверять свою логику, обрабатывать данные и возвращать реальные результаты, полученные в результате выполнения кода. Это превращает модель из простого "думателя" в активного "исполнителя".

Основные особенности включают в себя:

- **Динамическое выполнение кода на Python:** Модель генерирует и выполняет код на языке Python в изолированной среде.
- **Работа с файлами:** Загрузка, обработка и скачивание файлов (в форматах CSV, JSON, изображений и других).
- **Анализ данных:** Выполнение расчетов, статистический анализ и преобразование данных в режиме реального времени.
- **Обратная связь в реальном времени:** Модель анализирует результаты выполнения кода и может предлагать улучшения или исправлять ошибки.
- **Решение сложных задач:** Решайте математические задачи, выполняйте симуляции и решайте логические головоломки с помощью исполняемого кода.

## Наиболее распространенные сценарии использования.

| Случай использования | Пример |
| --- | --- |
| **Анализ данных** | Разбор файла в формате CSV и создание сводной статистики. |
| **Математика и физика** | Решение дифференциальных уравнений или моделирование физических процессов. |
| **Преобразование файлов** | Преобразование между различными форматами данных (например, JSON в CSV и обратно). |
| **Создание прототипов** | Тестирование алгоритмов и концепций перед их формальной реализацией. |

## Простой пример.

Вот как использовать Code Interpreter с API ответов OpenAI:

```
from openai import OpenAI

client = OpenAI(
    base_url={openai_endpoint},
    api_key={auth_key_or_token}
)

# Get response using the code_interpreter tool
response = client.responses.create(
    model={model_deployment},
    instructions="You are an AI assistant that provides information. Use the python tool to run code for math problems.",
    input="What is the square root of 16?",
    tools=[{"type": "code_interpreter",
            "container": {"type": "auto"}}]
)
print(response.output_text)
```

Результат работы этого кода будет примерно таким:

```
The square root of 16 is 4.
```

Более того, изучение деталей объекта **ответа**, возвращаемого моделью, показывает, что результат был вычислен и отправлен модели с использованием динамически генерируемого кода на языке Python, например, такого:

```
import math

# Calculate the square root of 16
square_root = math.sqrt(16)
square_root
```

## Как работает инструмент code_interpreter.

Общий процесс использования инструмента "code_interpreter" следующий:

1. **Вы отправляете запрос:** Добавьте `code_interpreter` в массив ваших инструментов.
2. **Модель анализирует задачу:** Модель определяет, требуется ли выполнение кода.
3. **Модель генерирует код:** Модель создает фрагменты кода на языке Python для выполнения поставленной задачи.
4. **Выполнение кода:** Код выполняется в изолированной среде с доступом к стандартным библиотекам (например, *pandas*, *numpy* и *math*).
5. **Результаты:** Модель получает полученные результаты и использует их для формирования своего ответа.

## Лучшие практики.

- **Будьте конкретны:** Четко опишите формат данных и ожидаемый результат. Многие модели используют внутренне название "*инструмент Python*", чтобы идентифицировать инструмент `code_interpreter` – поэтому используйте эту терминологию в своих инструкциях.
- **Предоставляйте контекст:** Включайте в свои запросы соответствующие знания предметной области.
- **Проверка результатов:** Всегда проверяйте код, сгенерированный искусственным интеллектом, на предмет корректности, прежде чем использовать его в производственной среде.
- **Контроль затрат:** Выполнение кода требует использования токенов; сложные операции могут потреблять больше ресурсов.
- **Использование библиотек:** Распространенные пакеты, такие как pandas, numpy и matplotlib, уже установлены по умолчанию.
- **Обработка ошибок:** Модель может обнаруживать ошибки и автоматически пытаться их исправлять.

## Ограничения, о которых следует знать.

- Выполнение программ происходит в изолированной среде, без доступа к внешней сети.
- Некоторые библиотеки могут быть недоступны; сообщите модели, если стандартная библиотека не работает.
- Ограничения по времени выполнения применяются к операциям, требующим длительного времени обработки.
- Код выполняется с учетом **ограничений по объему памяти** — для работы с очень большими наборами данных может потребоваться их потоковая обработка или разбиение на части.

# Используйте инструмент веб-поиска.

Инструмент *web_search* позволяет вашей модели получать актуальную информацию из интернета во время формирования ответа.

## Что такое инструмент "web_search"?

Инструмент web_search предоставляет модели генеративного искусственного интеллекта доступ к актуальной внешней информации во время работы. Вместо того чтобы полагаться только на данные обучения, модель может отправлять запрос в поисковую систему, анализировать соответствующие источники и генерировать ответ, основанный на самой свежей информации.

Это особенно полезно в тех случаях, когда информация может часто меняться, например, цены, выход новых продуктов, изменения в политике или текущие события.

Основные особенности включают в себя:

- **Получение актуальной информации в реальном времени** – Получайте свежую информацию, которая отсутствует в данных, используемых для обучения статической модели.
- **Ответы, основанные на источниках:** Формирование ответов на основе извлеченной информации из веб-контента.
- **Снижение риска возникновения галлюцинаций** – Повышение надежности за счет проверки информации из внешних источников.
- **Автоматическая генерация запросов:** Модель определяет, когда и каким образом выполнять поиск, основываясь на намерениях пользователя.
- **Бесшовный пользовательский опыт:** Поиск и формирование ответов происходят в едином процессе.

## Наиболее распространенные сценарии использования.

| Случай использования | Пример |
| --- | --- |
| **Актуальные события** | Кратко изложите основные обновления по последним новостям в сфере технологий. |
| **Исследование рынка** | Сравнение последних характеристик продуктов или цен у различных поставщиков. |
| **Мониторинг соблюдения нормативных требований** | Проверьте, не изменились ли какие-либо правила или рекомендации. |
| **Проверка фактов** | Проверка утверждений путем сопоставления с надежными общедоступными источниками. |

## Простой пример.

Вот минимальный пример использования API ответов OpenAI с включенным веб-поиском:

```
from openai import OpenAI

client = OpenAI(
    base_url={openai_endpoint},
    api_key={auth_key_or_token}
)

# Get response using the web_search tool
response = client.responses.create(
    model={model_deployment},
    instructions="You are an AI assistant. Use web search when current information is required.",
    input="What are three major announcements from Microsoft Build this week?",
    tools=[{"type": "web_search"}]
)

print(response.output_text)
```

Результат будет зависеть от текущих данных из сети, но он должен содержать краткий ответ, основанный на последних источниках информации.

## Как работает инструмент веб-поиска.

Общий процесс использования инструмента веб-поиска следующий:

1. **Вы отправляете запрос:** Добавьте инструмент поиска в интернете в массив инструментов.
2. **Модель анализирует вопрос** – она определяет, необходимы ли для ответа свежие данные из сети Интернет.
3. **Выполняется поиск:** Модель формирует один или несколько поисковых запросов.
4. **Результаты анализируются:** Отбираются и обобщаются соответствующие страницы.
5. **Ответ сформирован** – Модель объединяет результаты поиска для формирования окончательного ответа.

## Лучшие практики.

- **Задавайте вопросы, учитывающие временной аспект, четко и ясно.** – Используйте слова, такие как "последний", "текущий" или указывайте диапазоны дат, когда это необходимо.
- **Устанавливайте требования к источникам:** Предлагайте использовать авторитетные или официальные источники, когда важна точность информации.
- **Запрашивайте краткие ответы:** Просите предоставлять короткие выжимки с основными моментами, чтобы избежать излишней информации.
- **Проверяйте ключевые факты:** В ситуациях, где многое поставлено на карту, независимо подтверждайте важные утверждения.
- **Отслеживание использования и задержек:** Использование веб-сервисов может увеличить время отклика и расход токенов.

## Ограничения, о которых следует знать.

- Результаты зависят от информации, которая находится в открытом доступе и может быть проиндексирована на момент запроса.
- Качество исходных данных может быть разным, поэтому окончательный результат все равно может потребовать проверки человеком.
- Полученные результаты могут меняться со временем, поэтому повторные запросы могут давать разные ответы.
- В некоторых средах могут действовать региональные ограничения, политики безопасности или сетевые настройки, которые влияют на доступ к веб-ресурсам.

При правильном использовании инструмент web_search позволяет вашей модели переходить от статичных знаний к актуальным и основанным на конкретных источниках ответам, которые более полезны в реальных рабочих процессах.

# Используйте инструмент поиска файлов (file_search).

Инструмент *file_search* позволяет вашей модели извлекать релевантную информацию из загруженных вами документов во время формирования ответа.

## Что такое инструмент поиска файлов (file_search)?

Инструмент `file_search` помогает модели отвечать на вопросы, используя конфиденциальные или специализированные файлы, такие как документы политик, руководства, контракты и внутренние базы знаний. Вместо того чтобы полагаться только на общие данные обучения, модель может искать информацию в проиндексированном содержимом файлов и предоставлять обоснованные ответы.

Это особенно полезно, когда вам нужны точные ответы, основанные на проверенных внутренних документах.

Основные особенности включают в себя:

- **Ответы, основанные на предоставленных документах:** Ответы формируются на основе загруженных вами файлов.
- **Семантический поиск** – Находит релевантные фрагменты текста, основываясь на смысле, а не только на точном совпадении ключевых слов.
- **Интеграция с векторной базой данных:** Поиск по одному или нескольким индексированным наборам документов.
- **Ссылки и прозрачность:** Включайте соответствующие результаты для отладки и обеспечения прослеживаемости.
- **Более высокая применимость к конкретным предприятиям:** Используйте знания, специфичные для организации, при формировании результатов работы модели.

## Наиболее распространенные сценарии использования.

| **Юридический анализ** | Поиск конкретных положений в различных документах контракта |

## Простой пример.

Вот пример использования API ответов OpenAI с включенной функцией поиска по файлам:

```
from openai import OpenAI

client = OpenAI(
    base_url={openai_endpoint},
    api_key={auth_key_or_token}
)

# Create vector store and upload a file
vector_store = client.vector_stores.create(name="policy-docs")
client.vector_stores.files.upload_and_poll(
    vector_store_id=vector_store.id,
    file=open("expenses_policy.pdf", "rb")
)

# Get response using the file_search tool
response = client.responses.create(
    model=model_deployment,
    instructions="You are an AI assistant that provides information from HR policy documents.",
    input="What's the maximum amount I can claim for a taxi ride?",
    tools=[{
        "type": "file_search",
        "vector_store_ids": [vector_store.id]
    }],
    include=["file_search_call.results"]
)
print(response.output_text)
```

В этом процессе модель просматривает индексированный файл с политиками и использует полученные фрагменты текста для формирования обоснованного ответа.

## Как работает инструмент поиска файлов.

Общий процесс использования инструмента поиска файлов выглядит следующим образом:

1. **Вы готовите файлы:** Загружаете документы в векторную базу данных.
2. **Вы отправляете запрос:** Включите `file_search` в массив инструментов и укажите идентификаторы векторных хранилищ.
3. **Модель выполняет поиск информации:** Она ищет в проиндексированных фрагментах релевантный контент.
4. **Результаты вводятся в систему:** Модели предоставляются соответствующие фрагменты текста.
5. **Ответ сформирован** – Модель генерирует ответ, используя информацию, извлеченную из предоставленных документов.

## Лучшие практики.

- Используйте высококачественные исходные файлы. Чистые и актуальные документы повышают точность поиска.
- **Формулируйте четкие запросы:** Задавайте конкретные вопросы, чтобы уменьшить количество неточных результатов.
- **Тщательно структурируйте векторные хранилища данных** – Разделяйте различные области (например, отдел кадров, юридический отдел, финансы), если это целесообразно.
- **Включайте результаты поиска в процессе разработки.** – Используйте функцию "включить ответ" для отладки.
- **Проверка ответов для критически важных процессов** – Обеспечьте ручную проверку в ситуациях, требующих особой точности.

## Ограничения, о которых следует знать.

- Качество ответа зависит от качества документа, его полноты и соответствия конкретному запросу.
- Очень крупные магазины или магазины, предлагающие широкий ассортимент товаров, могут предоставлять менее конкретную информацию о товарах.
- Обновленные исходные файлы могут потребовать повторной индексации, прежде чем новый контент станет доступным для поиска.
- Извлечение информации улучшает процесс принятия решений, но не заменяет собой экспертную оценку человека при принятии важных решений.

При правильном использовании инструмент `file_search` превращает универсальную модель в специализированного помощника, который может отвечать на вопросы, опираясь на документы, которые действительно используются вашей командой.

# Используйте инструмент "Функция".

Инструмент "функция" позволяет вашей модели вызывать функции, определенные разработчиком, для получения данных или выполнения действий в процессе формирования ответа.

## Что такое инструмент "функция"?

Функция "вызов инструментов" (function calling) позволяет модели определять, когда следует вызывать предопределенные инструменты, доступные в вашем приложении. Модель не выполняет логику вашего приложения напрямую. Вместо этого, она возвращает структурированный запрос на вызов функции, ваш код запускает эту функцию, а затем результат работы функции передается обратно модели.

Эта схема идеально подходит для интеграции логики работы моделей с реальными системами, такими как API, базы данных, бизнес-процессы и вспомогательные функции.

Основные особенности включают в себя:

- **Структурированные запросы на вызов функций:** Модель генерирует явные запросы на выполнение определенных функций.
- **Управление выполнением со стороны разработчика:** Ваше приложение определяет, как и где будут выполняться функции.
- **Надежный шаблон интеграции:** Безопасный вызов API, внутренних сервисов или вспомогательных утилит.
- **Многоэтапная обработка запросов:** Возвращайте результаты работы инструмента и позволяйте модели продолжить процесс рассуждения.
- **Обоснованные ответы:** Ответы могут содержать актуальные данные, полученные непосредственно из системы.

## Наиболее распространенные сценарии использования.

| Случай использования | Пример |
| --- | --- |
| **Интеграция с системой** | Вызов внутреннего API для получения информации об учетной записи или заказе. |
| **Автоматизация задач** | Автоматическое выполнение процессов, таких как создание заявок или отправка уведомлений. |
| **Поиск данных** | Перед ответом на вопрос необходимо проверить бизнес-правила или справочные таблицы. |

## Простой пример.

Вот пример, который демонстрирует... `get_time` функция, и позволяет модели вызывать ее по мере необходимости:

```
import time
from openai import OpenAI

# Function to get the current time
def get_time():
    return f"The time is {time.strftime('%Y-%m-%d %H:%M:%S', time.localtime())}"

# Main function
def main():
    client = OpenAI(
        base_url={openai_endpoint},
        api_key={auth_key_or_token}
    )

    function_tools = [
        {
            "type": "function",
            "name": "get_time",
            "description": "Get the current time"
        }
    ]

    # Initialize messages with a system prompt
    messages = [
        {"role": "developer", "content": "You are an AI assistant that provides information."},
    ]

    # Loop until the user types 'quit'
    while True:
        prompt = input("\nEnter a prompt (or type 'quit' to exit)\n")
        if prompt.lower() == "quit":
            break

        # Append the user prompt to the messages
        messages.append({"role": "user", "content": prompt})

        # Get initial response
        response = client.responses.create(
            model=model_deployment,
            input=messages,
            tools=function_tools
        )

        # Append model output to the messages
        messages += response.output

        # Was there a function call?
        for item in response.output:
            if item.type == "function_call" and item.name == "get_time":
                current_time = get_time()
                messages.append({
                    "type": "function_call_output",
                    "call_id": item.call_id,
                    "output": current_time
                })

                # Get a follow up response using the tool output
                response = client.responses.create(
                    model=model_deployment,
                    instructions="Answer only with the tool output.",
                    input=messages,
                    tools=function_tools
                )

        print(response.output_text)

# Run the main function when the script starts
if __name__ == '__main__':
    main()
```

В этом процессе модель определяет, когда следует выполнить вызов. `get_time`Ваш код запускает функцию, и затем модель возвращает окончательный ответ, основанный на полученных данных. Поскольку пользователь может ввести любой запрос, модель должна определить, когда ей необходимо вызвать эту функцию. Если это происходит, в ответе на запрос будет содержаться вызов функции, который приложение должно реализовать перед отправкой нового запроса вместе с результатами работы функции, чтобы модель могла их обработать.

Результат может выглядеть примерно так:

```
Enter a prompt (or type 'quit' to exit)
Hello

Hello! How can I help you today?

Enter a prompt (or type 'quit' to exit)
What time is it?

The time is 2026-03-19 17:17:41.

Enter a prompt (or type 'quit' to exit)
```

Первый запрос пользователя ("Здравствуйте") не требовал использования инструмента функции, поэтому модель ответила как обычно. Второй запрос ("Который час?") активировал у модели выбор... `get_time` Функция, которую она указала в своем ответе. Затем код приложения выполнял эту функцию и возвращал результаты модели, которая, в свою очередь, отправляла второй ответ, содержащий результаты работы функции.

Совет.

В этом примере используется одна функция без параметров. Вы можете настроить инструмент для использования нескольких функций, с параметрами или без них. Для получения дополнительной информации о том, как указать параметры функции, обратитесь к разделу... [OpenAI developers guide](https://developers.openai.com/api/docs/guides/function-calling).

## Как работает эта функция (или инструмент).

Общий процесс использования инструмента функции следующий:

1. **Вы определяете инструменты:** Предоставьте одно или несколько определений функций в массиве `tools`.
2. **Модель оценивает запрос** – она определяет, требуется ли вызов функции.
3. **Модель выдает вызов функции:** Ответ содержит имя функции и метаданные вызова.
4. Ваше приложение выполняет логические операции – запустите функцию сопоставления в вашем коде.
5. **Функция возвращает результат:** Отправьте... `function_call_output` элемент с результатом.
6. **Модель завершает ответ** – Она включает результаты работы инструментов в окончательный ответ.

## Лучшие практики.

- **Сохраняйте сфокусированность инструментов:** Небольшие функции, предназначенные для выполнения конкретных задач, легче контролировать и тестировать.
- **Проверка входных данных функции:** Никогда не доверяйте аргументам инструментов слепо в производственных системах.
- **Обрабатывайте ошибки корректно:** Возвращайте понятные сообщения об ошибках, которые модель сможет интерпретировать.
- **Отслеживание использования инструментов логирования** – Мониторинг вызовов, задержек и частоты ошибок для отладки и контроля.
- Ограничьте выполнение критически важных операций – требуйте явного разрешения для действий, имеющих серьезные последствия.

## Ограничения, о которых следует знать.

- Модель запрашивает выполнение определенных действий, но ваша программа должна их осуществлять.
- Неправильные или неожиданные аргументы, передаваемые инструментам, могут возникать, и их необходимо проверять.
- Задержка работы инструментов может увеличить общее время отклика системы.
- Использование функций повышает надежность системы, но окончательные результаты все равно требуют проверки, особенно при принятии важных решений.

При правильном использовании, этот инструмент позволяет превратить модель, предназначенную для генерации текста, в систему управления, которая может взаимодействовать с реальными системами контролируемым и поддающимся проверке образом.
