# Создайте решение для мультимодального анализа с помощью сервиса Azure Content Understanding.

# Введение.

В настоящее время организации полагаются на информацию, которая часто содержится в различных форматах контента, таких как документы, изображения, видео и аудиозаписи. Извлечение информации из этого контента может быть сложной, трудоемкой и затратной по времени задачей. Поэтому организациям зачастую приходится разрабатывать решения, основанные на использовании нескольких технологий для анализа контента, в зависимости от используемых форматов.

Azure Content Understanding – это многофункциональный сервис, который упрощает создание интеллектуальных инструментов анализа данных, способных извлекать информацию из контента практически в любом формате.

![Схема работы сервиса Azure Content Understanding, демонстрирующая извлечение информации из документов, аудиофайлов, видео и изображений.](https://learn.microsoft.com/en-us/training/wwl-data-ai/analyze-content-ai/media/content-understanding.png)

В этом модуле вы познакомитесь с возможностями сервиса Azure Content Understanding и узнаете, как использовать его для создания собственных аналитических инструментов.

Примечание.

Мы понимаем, что разные люди предпочитают учиться разными способами. Вы можете пройти этот модуль в формате видео или изучить материалы в виде текста и изображений. Текст содержит более подробную информацию, чем видео, поэтому в некоторых случаях вам может быть полезно использовать его как дополнительный материал к видеолекции.

# Что такое Azure Content Understanding?

Azure Content Understanding – это сервис генеративного искусственного интеллекта, который позволяет извлекать ценную информацию и данные из различных типов контента. С помощью сервиса Content Understanding вы можете быстро создавать приложения, которые анализируют сложные данные и генерируют результаты, которые можно использовать для автоматизации и оптимизации процессов.

Функция "Понимание контента" доступна через платформу Microsoft Foundry. Для ее использования необходимо создать ресурс Microsoft Foundry в вашей подписке Azure. Вы можете разрабатывать и управлять решением для анализа контента:

- На портале Microsoft Foundry.
- В студии анализа контента.
- Используя API для понимания контента...

## Мультимодальный анализ контента.

Функция "Понимание контента" позволяет извлекать информацию из различных типов данных, что дает вам возможность использовать единый сервис с простым и унифицированным процессом разработки для создания решений по анализу мультимедийного контента.

### Документы и формы.

Вы можете использовать функцию "Понимание содержимого" для анализа документов и форм, а также для извлечения конкретных значений полей. Например, вы можете извлекать ключевые данные из счета-фактуры для автоматизации процесса обработки платежей.

![Скриншот счета-фактуры, который анализируется системой распознавания и понимания контента.](https://learn.microsoft.com/en-us/training/wwl-data-ai/analyze-content-ai/media/document-analysis.png)

### Изображения.
Иллюстрации.
Фотографии.

Вы можете анализировать изображения для получения информации из визуальных данных, таких как графики, выявления физических дефектов в продуктах или других предметах, обнаружения наличия определенных объектов или людей, а также определения другой информации, представленной визуально.

![Скриншот изображения, которое анализируется системой понимания контента.](https://learn.microsoft.com/en-us/training/wwl-data-ai/analyze-content-ai/media/image-analysis.png)

### Аудио.

Анализ аудио позволяет автоматизировать такие задачи, как создание кратких обзоров телефонных конференций, определение эмоциональной окраски записей разговоров с клиентами или извлечение ключевых данных из голосовых сообщений.

![Скриншот аудиофайла, который анализируется системой распознавания и понимания контента.](https://learn.microsoft.com/en-us/training/wwl-data-ai/analyze-content-ai/media/audio-analysis.png)

### Видео.

Видеоматериалы составляют значительную часть данных, собираемых сегодня, и вы можете использовать функцию "Понимание контента" для анализа видео и извлечения полезной информации, которая может быть применена в различных сценариях. Например, для выделения ключевых моментов из записей видеоконференций, для создания кратких обзоров презентаций или для обнаружения определенных действий на записях с камер видеонаблюдения.

# Создайте инструмент для анализа понимания контента.

Решения для анализа контента основаны на создании *анализатора*, который обучен извлекать определенную информацию из конкретного типа контента, используя заданную вами *схему*.

Высокоуровневый процесс создания решения для понимания контента включает в себя следующие этапы:

![Схема, иллюстрирующая пример документа, используемого для создания структуры данных (схемы) для анализатора, который используется клиентским приложением.](https://learn.microsoft.com/en-us/training/wwl-data-ai/analyze-content-ai/media/analyzer.png)

1. Создайте ресурс Foundry.
2. Определите схему понимания контента для информации, которую необходимо извлечь. Эта схема может быть основана на примере контента и шаблоне анализатора.
3. Создайте анализатор на основе разработанной схемы.
4. Используйте анализатор для извлечения или создания полей из нового контента.

Вам предоставляется множество шаблонов анализаторов, которые помогут вам быстро создать подходящий анализатор для ваших задач. Кроме того, благодаря возможностям генеративного искусственного интеллекта в сервисе Content Understanding, вы можете использовать минимальный объем обучающих данных для определения структуры данных на основе примеров. Во многих случаях сервис автоматически и точно определяет значения данных в образцах контента, соответствующие элементам структуры, хотя вы также можете явно указывать поля в таких материалах, как документы, чтобы повысить эффективность вашего анализатора.

## Создание анализатора с помощью платформы Content Understanding Studio.

Хотя вы можете разработать комплексное решение для анализа контента с помощью API или специализированного SDK, Content Understanding Studio предоставляет визуальный интерфейс для создания проекта, определения схемы анализа контента, а также для разработки и тестирования аналитического модуля.

Совет.

Только определенные готовые модели доступны для непосредственного использования в портале Microsoft Foundry. Для создания и тестирования собственных аналитических инструментов используйте...[Content Understanding Studio](https://ai.azure.com/contentunderstanding)**.

### Создание проекта по анализу и пониманию контента.

В студии понимания контента вы можете создать новый проект, связанный с ресурсом Microsoft Foundry. Создание проекта обеспечивает выделение необходимых ресурсов Azure для поддержки вашего решения в области понимания контента, включая хранилище и ресурс "хранилище ключей" для хранения конфиденциальной информации, такой как учетные данные и ключи.

![Скриншот пользовательского интерфейса создания нового проекта в программе Content Understanding Studio.](https://learn.microsoft.com/en-us/training/wwl-data-ai/analyze-content-ai/media/new-project.png)

Примечание.

Схемы понимания контента можно создавать только в регионах Azure, где эта служба поддерживается. Для получения дополнительной информации см. раздел "**".[Content Understanding region and language support](/en-us/azure/ai-services/content-understanding/language-region-support)**.

### Определение понятия "схема".

После создания проекта первым шагом в разработке анализатора является определение схемы для контента, который будет обрабатываться, и информации, которую он должен извлекать. Content Understanding Studio предоставляет интерфейс редактора схем, в котором вы можете загрузить файл (документ, изображение, аудио- или видеофайл), на основе которого должна быть создана схема. Затем вы можете применить подходящий шаблон схемы и определить конкретные поля, которые анализатор должен идентифицировать.

![Скриншот пользовательского интерфейса "Определение схемы" в программе Content Understanding Studio.](https://learn.microsoft.com/en-us/training/wwl-data-ai/analyze-content-ai/media/slide-schema.png)

Примечание.

Шаблоны и типы полей, доступные в схеме, зависят от типа содержимого файла, на котором основана эта схема. Некоторые типы содержимого поддерживают дополнительные опциональные функции, такие как извлечение штрих-кодов и формул из текста в документах. Для получения дополнительной информации об использовании функционала "Понимание содержимого" с различными типами содержимого, ознакомьтесь со следующими статьями в технической документации продукта:

- **[Content Understanding document solutions](/en-us/azure/ai-services/content-understanding/document/overview)**
- **[Content Understanding image solutions](/en-us/azure/ai-services/content-understanding/image/overview)**
- **[Content Understanding audio solutions](/en-us/azure/ai-services/content-understanding/audio/overview)**
- **[Content Understanding video solutions](/en-us/azure/ai-services/content-understanding/video/overview)**

### Тестирование.

Вы можете протестировать схему анализатора в любое время в процессе разработки, запустив анализ на примере файла, используемого для определения схемы, или на других загруженных файлах. Результаты теста включают извлеченные значения полей и вывод в формате JSON, который анализатор возвращает клиентским приложениям.

![Скриншот результатов анализа, полученных в программе Content Understanding Studio.](https://learn.microsoft.com/en-us/training/wwl-data-ai/analyze-content-ai/media/slide-analysis.png)

### Создание анализатора.

Когда вы будете удовлетворены работой вашей схемы, вы можете создать анализатор. Создание анализатора делает его доступным для клиентских приложений через конечную точку ресурса Microsoft Foundry, связанного с вашим проектом.

После создания вашего анализатора вы можете продолжить его тестирование в среде Content Understanding Studio и уточнять схему, чтобы создавать новые версии с различными возможностями.

# Используйте API для анализа содержимого.

API для анализа контента предоставляет программный интерфейс, который можно использовать для создания, управления и использования инструментов анализа данных.

Для использования API ваше клиентское приложение отправляет HTTP-запросы к компоненту Content Understanding, связанному с вашим ресурсом Microsoft Foundry, передавая один из ключей авторизации в заголовке запроса. Вы можете получить адрес компонента и ключи в портале Azure или в портале Microsoft Foundry. Кроме того, вы можете использовать API Microsoft Foundry для программного подключения к проекту с использованием вашей учетной записи Entra ID.

## Использование API для анализа контента.

Одно из наиболее распространенных применений API заключается в отправке данных для анализа существующему анализатору, который вы ранее создали, и получении результатов этого анализа. Запрос на анализ возвращает идентификатор операции (operation ID), представляющий собой асинхронную задачу. Ваше клиентское приложение должно использовать другой запрос, чтобы передать этот идентификатор обратно в конечную точку и получить статус выполнения операции. Возможно, потребуется несколько запросов для проверки статуса, пока операция не будет завершена, после чего результаты будут возвращены в формате JSON.

Например, для анализа документа клиентское приложение может отправить запрос типа POST на... `analyze` функция, содержащая следующий блок данных в формате JSON:

```
POST {endpoint}/contentunderstanding/analyzers/{analyzer}:analyze?api-version=2025-11-01
{
  "inputs": [
    {
      "url": "https://host.com/doc.pdf"
    }
  ]
}
```

Примечание.

Вы можете указать URL-адрес для расположения файла с содержимым, как показано здесь. Чтобы отправить данные двоичного файла напрямую, используйте... `analyzeBinary` вместо этого была проведена операция.

При условии, что запрос был успешно аутентифицирован и отправлен, ответ будет выглядеть примерно так:

```
Operation-Id: 1234abcd-1234-abcd-1234-abcd1234abcd
Operation-Location: {endpoint}/contentunderstanding/analyzerResults/1234abcd-1234-abcd-1234-abcd1234abcd?api-version=2025-11-01
{
  "id": "1234abcd-1234-abcd-1234-abcd1234abcd",
  "status": "NotStarted"
}
```

Ваше клиентское приложение должно использовать идентификатор операции, который был возвращен, для проверки статуса выполнения операции до тех пор, пока она не будет успешно завершена (или не завершится с ошибкой), отправляя запрос GET на указанный адрес. `analyzerResults` конечная точка.

```
GET {endpoint}/contentunderstanding/analyzerResults/1234abcd-1234-abcd-1234-abcd1234abcd?api-version=2025-11-01
```

После успешного завершения операции ответ содержит данные в формате JSON, представляющие результаты анализа. Конкретные результаты зависят от содержимого и структуры данных.

Примечание.

Для получения дополнительной информации об API для понимания контента, пожалуйста, обратитесь к разделу "**".[reference documentation](/en-us/rest/api/contentunderstanding/operation-groups)**.
