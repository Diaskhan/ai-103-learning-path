# Разработайте комплексное решение с использованием нескольких агентов, применяя платформу Microsoft Agent Framework.

# Введение.

Искусственные интеллект-агенты предлагают мощное сочетание технологий и способны выполнять задачи с использованием генеративного искусственного интеллекта. Однако, в некоторых случаях, задача может быть слишком сложной для выполнения одним агентом. В таких ситуациях стоит рассмотреть **многоагентное решение**. Многоагентное решение позволяет агентам взаимодействовать и сотрудничать в рамках одного разговора.

Представьте себе, что вы пытаетесь решить распространенные задачи в области DevOps, такие как мониторинг производительности приложений, выявление проблем и внедрение исправлений. Многоагентная система может состоять из четырех специализированных агентов, работающих совместно:

- Агент мониторинга непрерывно собирает журналы и метрики, выявляет аномалии с использованием методов обработки естественного языка (NLP) и генерирует оповещения в случае возникновения проблем.
- Агент анализа первопричин затем сопоставляет эти аномалии с недавними изменениями в системе, используя модели машинного обучения или предопределенные правила, чтобы точно определить основную причину проблемы.
- Как только определена основная причина проблемы, автоматизированный агент развертывания приступает к работе, чтобы устранить неполадки или отменить внесенные изменения, взаимодействуя с конвейерами непрерывной интеграции и доставки (CI/CD) и выполняя скрипты развертывания.
- В заключение, система отчетности формирует подробные отчеты, обобщающие выявленные аномалии, их причины и способы устранения, а также уведомляет заинтересованные стороны по электронной почте или через другие каналы связи.

Эта модульная, масштабируемая и интеллектуальная многоагентная система оптимизирует процесс разработки и эксплуатации (DevOps). Агенты взаимодействуют друг с другом для снижения необходимости ручного вмешательства и повышения эффективности, обеспечивая при этом своевременную коммуникацию и решение возникающих проблем.

В этом модуле вы узнаете, как использовать мощные возможности платформы Microsoft Agent для разработки и организации работы интеллектуальных агентов, которые совместно решают сложные задачи. Вы также изучите различные типы моделей взаимодействия и используйте платформу Microsoft Agent для создания собственных ИИ-агентов, способных сотрудничать в рамках комплексного решения.

После завершения этого модуля вы сможете:

- Создавайте ИИ-агентов с помощью SDK платформы Microsoft Agent Framework.
- Используйте инструменты и плагины вместе с вашими ИИ-агентами.
- Понимание различных типов схем оркестровки.
- Разрабатывать решения с использованием многоагентных систем.

# Понимание структуры Microsoft Agent.

Фреймворк Microsoft Agent – это открытая платформа разработки (SDK), которая позволяет разработчикам интегрировать модели искусственного интеллекта в свои приложения. Этот фреймворк предоставляет всестороннюю поддержку для создания агентов, работающих на основе ИИ, которые могут функционировать автономно или взаимодействовать с другими агентами для выполнения сложных задач.

## Что такое платформа Microsoft Agent?

Фреймворк Microsoft Agent предназначен для помощи разработчикам в создании интеллектуальных агентов, которые могут обрабатывать пользовательские запросы, принимать решения и выполнять задачи автономно, используя большие языковые модели и традиционные методы программирования. Этот фреймворк предоставляет структурированные компоненты для определения рабочих процессов, управляемых искусственным интеллектом, что позволяет агентам беспрепятственно взаимодействовать с пользователями, API и внешними сервисами.

### Основные понятия.

Фреймворк Microsoft Agent предоставляет гибкую архитектуру, состоящую из следующих ключевых компонентов:

- Агенты.

  Агенты – это интеллектуальные сущности, работающие на основе искусственного интеллекта, способные к логическому мышлению и выполнению задач. Они используют большие языковые модели, инструменты и историю разговоров для принятия решений в режиме реального времени и реагирования на потребности пользователей.
- Оркестровка агентов.

  Несколько агентов могут совместно работать для достижения общей цели, используя различные схемы организации взаимодействия. Фреймворк Microsoft Agent поддерживает несколько таких схем, предоставляя унифицированный интерфейс для создания и запуска, что позволяет легко переключаться между ними без необходимости переписывать логику работы ваших агентов.

Эта платформа включает в себя несколько ключевых функций, которые обеспечивают работу агентов:

- Клиентские приложения для чата.

  Клиентские приложения для работы с чат-ботами предоставляют абстракции для подключения к сервисам искусственного интеллекта от различных поставщиков через единый интерфейс. Поддерживаются такие поставщики, как Azure OpenAI, OpenAI, Anthropic и другие, посредством... [далее следует описание способа подключения]. `BaseChatClient` абстракция.
- Интеграция инструментов и функциональности.

  **Инструменты** позволяют агентам расширять свои возможности за счет использования пользовательских функций и встроенных сервисов. Агенты могут автоматически вызывать инструменты для интеграции с внешними API, выполнения кода, поиска файлов или доступа к информации в интернете. Фреймворк поддерживает как инструменты с пользовательскими функциями, так и встроенные инструменты, такие как "Интерпретатор кода", "Поиск по файлам" и "Поиск в интернете".
- Управление диалогами.

  Агенты могут сохранять историю переписки в ходе нескольких взаимодействий, используя... `AgentSession`Это позволяет им отслеживать предыдущие взаимодействия и соответствующим образом адаптировать ответы. Структурированная система обмена сообщениями использует роли (ПОЛЬЗОВАТЕЛЬ, АССИСТЕНТ, СИСТЕМА, ИНСТРУМЕНТ) для поддержания контекста разговора.

## Почему вам следует использовать платформу Microsoft Agent.

Фреймворк Microsoft Agent предоставляет надежную платформу для создания интеллектуальных, автономных и взаимодействующих между собой ИИ-агентов. Этот фреймворк позволяет интегрировать агентов из различных источников, включая сервис Microsoft Foundry Agent Service, и поддерживает как совместную работу нескольких агентов, так и взаимодействие человека с агентом. Агенты могут работать вместе для организации сложных рабочих процессов, где каждый агент специализируется на определенной задаче, такой как сбор данных, анализ или принятие решений. Фреймворк также упрощает процессы, в которых человек играет активную роль, позволяя агентам дополнять человеческое принятие решений, предоставляя полезные сведения или автоматизируя повторяющиеся задачи. Благодаря своей независимости от конкретного поставщика, этот фреймворк позволяет переключаться между различными платформами искусственного интеллекта без изменения кода, что делает его подходящим для создания гибких систем ИИ, начиная от простых чат-ботов и заканчивая сложными корпоративными решениями.

# Понимание принципов работы системы управления агентами.

Фреймворк оркестрации агентов, входящий в состав SDK Microsoft Agent Framework, позволяет проектировать, управлять и масштабировать сложные многоагентные процессы, не требуя ручной настройки взаимодействия между отдельными агентами. Вместо того чтобы полагаться на одного агента для управления всеми аспектами задачи, вы можете объединять несколько специализированных агентов. Каждый агент, выполняющий уникальную роль или обладающий определенной областью экспертизы, может сотрудничать для создания систем, которые будут более надежными, адаптивными и способными решать реальные проблемы совместными усилиями.

Объединяя агентов в группы, вы можете решать задачи, которые были бы слишком сложными для одного отдельного агента: от проведения параллельных анализов до создания многоступенчатых процессов обработки данных и управления динамической передачей задач между экспертами в зависимости от контекста.

## Почему важна координация работы множества агентов.

Системы, работающие на основе одного агента, часто имеют ограниченный функционал и ограничены одним набором инструкций или одной моделью запроса. Многоагентная оркестрация позволяет преодолеть это ограничение, предоставляя вам возможность:

- Назначьте каждому агенту определенные навыки, обязанности или точки зрения.
- Объединяйте результаты работы нескольких агентов для повышения качества принятия решений и точности.
- Оптимизируйте этапы рабочего процесса таким образом, чтобы работа каждого сотрудника основывалась на результатах работы предыдущего.
- Динамически перенаправляйте управление между агентами в зависимости от контекста или заданных правил.

Этот подход открывает возможности для создания более гибких, эффективных и масштабируемых решений, особенно в тех реальных приложениях, которые требуют сотрудничества, специализации или резервирования.

## Понимание принципов работы в фреймворке Microsoft Agent.

Фреймворк Microsoft Agent предоставляет **рабочие процессы** – структурированные последовательности шагов, используемые для выполнения задачи. Эти рабочие процессы могут включать один или несколько **искусственных интеллектов (ИИ)** наряду с другими компонентами для автоматизации сложных операций.

Рабочие процессы предоставляют разработчикам контроль над тем, как выполняются задачи, обеспечивают возможность **координированной работы нескольких агентов** и поддерживают функцию **сохранения состояния**, позволяющую сохранять и возобновлять выполнение рабочих процессов.

### Основные компоненты рабочего процесса.

#### Исполнители.
Исполняющие (функции).
Наследники (в контексте завещания).
Исполнительные органы.
(В зависимости от контекста, может также быть "исполнительные директоры" или "руководители").

Исполнители – это основные компоненты рабочего процесса. Они получают входные данные, выполняют определенные действия и генерируют результаты, которые способствуют завершению поставленной задачи.  
Исполнители могут представлять собой **агенты искусственного интеллекта** или компоненты, реализующие **специальную логику**.

*Пример:* Один сотрудник может анализировать запрос на организацию поездки, а другой, основываясь на результатах этого анализа, бронировать авиабилеты или отель.

#### Края.

Связи определяют, как сообщения передаются между исполнительными элементами, определяя логику и порядок выполнения операций. Фреймворк Microsoft Agent поддерживает несколько типов связей:

- **Прямые связи:** Соедините один элемент (исполнитель) непосредственно с другим в последовательности.  
  После того как агент искусственного интеллекта собирает данные, введенные пользователем, следующий этап – обработка запроса на бронирование.
- **Условные связи:** Активируются только при выполнении определенных условий.  
  Если номера в отеле недоступны, процесс перенаправляется к компоненту, который предлагает альтернативные даты или места размещения.
- **Условные переходы (Switch-Case):** Маршрутизация сообщений к различным обработчикам на основе заданных условий.  
  VIP-клиенты могут быть перенаправлены к сотруднику, предоставляющему услуги премиум-класса, в то время как остальные клиенты проходят стандартную процедуру.
- **Распределительные узлы:** Отправка одного сообщения нескольким исполнителям одновременно.  
  Пример: Один запрос может быть отправлен нескольким агентам – один будет проверять наличие авиабилетов, а другой – отелей.
- **Объединение входящих данных:** Объединение нескольких сообщений, полученных от разных исполнительных модулей, в одно сообщение для выполнения финального этапа.  
  После сбора информации о вариантах размещения в отеле и авиабилетах, специальный модуль обрабатывает эти данные и формирует единый план поездки.

#### **Мероприятия**

Фреймворк Microsoft Agent включает в себя встроенные события, предназначенные для повышения возможности отслеживания и упрощения процесса отладки во время выполнения рабочих процессов. Эти события помогают разработчикам контролировать ход выполнения, выявлять ошибки и анализировать производительность системы.

| **Название мероприятия** | **Описание** |
| --- | --- |
| **WorkflowStartedEvent** | Событие, которое срабатывает при начале выполнения рабочего процесса. |
| **WorkflowOutputEvent** |  Генерируется, когда рабочий процесс выдает результат. |
| **WorkflowErrorEvent** | Возникает при возникновении ошибки. |
| **ExecutorInvokeEvent** | Событие, которое срабатывает при запуске выполнения задачи исполнителем. |
| **ExecutorCompleteEvent** | Событие, которое срабатывает после завершения работы исполнителем. |
| **RequestInfoEvent** | Регистрируется при отправке внешнего запроса. |

В фреймворке Microsoft Agent предусмотрены инструменты для создания рабочих процессов, которые позволяют разработчикам проектировать, отслеживать и контролировать взаимодействие между несколькими ИИ-агентами и логическими компонентами для выполнения сложных задач. Они обеспечивают структурированность, гибкость и прозрачность приложений, работающих на основе агентов.

## Поддерживаемые шаблоны организации архитектуры приложения.

Фреймворк Microsoft Agent предоставляет в своем SDK несколько шаблонов организации взаимодействия между агентами, каждый из которых предлагает свой подход к координации работы этих агентов. Эти шаблоны разработаны таким образом, чтобы быть независимыми от конкретных технологий, что позволяет адаптировать их под ваши собственные задачи и интегрировать в существующие системы.

- **Параллельное выполнение задач:** Одновременно отправляйте одну и ту же задачу нескольким агентам и независимо собирайте результаты их работы. Это полезно для параллельного анализа, выполнения независимых подзадач или принятия решений на основе результатов работы нескольких компонентов (ансамбля).
- **Последовательная оркестровка** – Передача результатов работы одного агента следующему в заданном порядке. Идеально подходит для последовательных рабочих процессов, конвейеров и постепенной доработки.
- **Оптимизация передачи задач:** Динамическая передача контроля между операторами в зависимости от контекста или установленных правил. Идеально подходит для эскалации проблем, перенаправления запросов и маршрутизации к экспертам, когда за обработку одного запроса отвечает только один оператор.
- **Организация группового чата:** Координируйте совместную беседу между несколькими участниками (и, при необходимости, человеком), управляемую менеджером чата, который определяет, кто будет говорить следующим. Наиболее эффективно для мозговых штурмов, совместного решения проблем и достижения консенсуса.
- **Магнитная оркестровка** – это подход, основанный на управлении, который предполагает планирование, делегирование и адаптацию действий различных специалистов. Он подходит для решения сложных, многогранных задач, где путь к решению постоянно меняется.

## Единый процесс организации работы над оркестровкой.

Независимо от выбранной схемы организации, SDK для платформы Microsoft Agent предоставляет единообразный и удобный интерфейс для разработчиков, позволяющий создавать и запускать эти схемы. Обычно процесс выглядит следующим образом:

1. Определите своих агентов и опишите их возможности.
2. Выберите и создайте шаблон оркестровки, при необходимости добавьте управляющий агент.
3. При необходимости можно настроить обратные вызовы (callbacks) или преобразования для обработки входных и выходных данных нестандартным образом.
4. **Запустите среду выполнения**, чтобы управлять процессом работы.
5. Используйте возможности оркестровки для решения вашей задачи.
6. Получить результаты асинхронно, без блокировки выполнения программы.

Поскольку все шаблоны используют один и тот же основной интерфейс, вы можете легко экспериментировать с различными стратегиями организации процессов, не переписывая логику агентов и не изучая новые API. SDK абстрагирует сложность взаимодействия, координации и агрегации результатов работы агентов, позволяя вам сосредоточиться на разработке рабочих процессов, которые приносят результаты.

Инструмент многоагентной координации в SDK Microsoft Agent Framework предоставляет гибкий и масштабируемый способ создания интеллектуальных систем, объединяющих сильные стороны различных специализированных агентов. Благодаря встроенным шаблонам координации, унифицированной модели разработки и функциям управления выполнением во время работы, вы можете быстро создавать прототипы, дорабатывать и развертывать совместные системы искусственного интеллекта. Этот фреймворк предоставляет инструменты для преобразования нескольких агентов в слаженную команду по решению задач, будь то параллельные процессы, последовательные рабочие процессы или динамичные диалоги.

# Используйте параллельную оркестрацию.

**Параллельная оркестрация** позволяет нескольким агентам одновременно работать над одной и той же задачей. Каждый агент выполняет задачу независимо, а затем их результаты собираются и объединяются. Этот метод особенно эффективен, когда требуется разнообразие подходов или решений, например, во время мозгового штурма, групповых обсуждений или голосования.

![Схема потока параллельной оркестровки.](https://learn.microsoft.com/en-us/training/wwl-data-ai/orchestrate-semantic-kernel-multi-agent-solution/media/multi-agent-concurrent.png)

Этот подход полезен, когда вам требуются различные методы или идеи для решения одной и той же проблемы. Вместо того чтобы задействовать агентов последовательно, все они работают одновременно. Это ускоряет процесс и позволяет рассмотреть проблему с разных точек зрения.

Обычно результаты, полученные от каждого отдельного компонента системы, объединяются для формирования окончательного ответа, но это не всегда необходимо. Каждый компонент также может выдавать свой собственный, независимый результат, например, использовать инструменты для выполнения задач или обновлять различные базы данных по отдельности.

Агенты работают самостоятельно и не обмениваются результатами друг с другом. Однако, агент может вызывать другие ИИ-агенты, запуская собственную систему управления задачами в рамках своего процесса. Агентам необходимо знать, какие другие агенты доступны для выполнения задач. Эта схема позволяет либо вызывать всех зарегистрированных агентов каждый раз, либо выбирать конкретных агентов для работы в зависимости от поставленной задачи.

## Когда следует использовать параллельную оркестрацию?

В подобных ситуациях вам может быть полезно рассмотреть возможность использования паттерна параллельной оркестровки.

- Когда задачи могут выполняться одновременно, либо с использованием фиксированной группы агентов, либо путем динамического выбора искусственных интеллектов (ИИ) в зависимости от требований конкретной задачи.
- Когда для выполнения задачи требуются различные специализированные навыки или подходы (например, технические, деловые или творческие), которые работают независимо друг от друга, но вносят вклад в решение одной и той же проблемы.

Такой вид командной работы часто встречается в методах принятия решений, основанных на взаимодействии множества агентов, таких как:

- Генерация идей (или мозговой штурм).
- Комбинирование различных методов рассуждения (ансамблевое рассуждение).
- Принятие решений на основе голосования или консенсуса (кворума).
- Выполнение задач, где важна скорость, и одновременный запуск агентов позволяет значительно сократить время ожидания.

## Когда следует избегать одновременной оркестровки.

В следующих случаях рекомендуется избегать использования паттерна параллельной оркестровки:

- Агентам необходимо либо развивать работу друг друга, опираясь на уже выполненные задачи, либо использовать общую контекстную информацию в определенной последовательности.
- Эта задача требует четкой последовательности действий или предсказуемых, воспроизводимых результатов.
- Ограничения ресурсов, такие как лимиты на использование моделей, делают одновременный запуск агентов неэффективным или невозможным.
- Агенты не могут надежно координировать изменения в общих данных или внешних системах при одновременной работе.
- Не существует четкого способа разрешения конфликтов или противоречий между результатами, полученными от разных источников информации.
- Объединение результатов слишком сложно, или в результате этого снижается общее качество.

За счет параллельного выполнения агентов можно одновременно исследовать различные подходы, повысить эффективность и получить более глубокие знания. Однако важно выбирать этот подход только в том случае, если задачи действительно могут выполняться независимо друг от друга, а также учитывать ограничения ресурсов и сложности координации. При грамотной реализации с использованием SDK Microsoft Agent Framework, параллельная оркестрация может значительно улучшить ваши ИИ-рабочие процессы и процессы принятия решений.

# Используйте последовальную оркестровку.

В **последовательной оркестрации** агенты организованы в цепочку, где каждый агент обрабатывает задачу последовательно. Результат работы одного агента становится входными данными для следующего. Эта схема идеально подходит для рабочих процессов, в которых каждый этап зависит от предыдущего, например, для проверки документов, конвейеров преобразования данных или многоступенчатого анализа.

![Схема, демонстрирующая последовательную организацию работы, при которой агенты обрабатывают задачи в определенной последовательности. Результат работы одного агента передается следующему.](https://learn.microsoft.com/en-us/training/wwl-data-ai/orchestrate-semantic-kernel-multi-agent-solution/media/multi-agent-sequential.png)

Последовательная оркестрация наиболее эффективна для задач, которые необходимо выполнять поэтапно, причем каждый этап улучшает предыдущий. Порядок выполнения действий агентами фиксирован и определяется заранее, и сами агенты не принимают решения о том, что произойдет дальше.

## Когда следует использовать последовательную оркестровку?

Рассмотрите возможность использования паттерна последовательной оркестровки, когда ваш рабочий процесс включает в себя:

- Процессы, состоящие из нескольких этапов, которые должны выполняться в определенной последовательности, причем каждый этап зависит от предыдущего.
- Рабочие процессы обработки данных, в которых каждый этап добавляет важную информацию, необходимую для корректной работы следующего этапа.
- Задачи, в которых этапы не могут выполняться одновременно и должны выполняться последовательно, один за другим.
- Ситуации, требующие постепенных улучшений, такие как написание черновиков, проверка и доработка текста.
- Системы, в которых вы знаете, как работает каждый компонент, и которые способны обрабатывать задержки или сбои на любом этапе без остановки всего процесса.

## Когда следует избегать последовательной оркестровки.

Избегайте использования этой конструкции в следующих случаях:

- Этапы выполнения задач могут запускаться независимо друг от друга и параллельно, без ущерба для качества.
- Один специалист может эффективно выполнить всю задачу целиком.
- На ранних этапах работы могут возникать сбои или получаться результаты низкого качества, и не существует способа остановить или исправить дальнейшую обработку данных на основе выявленных ошибок.
- Агентам необходимо динамично взаимодействовать друг с другом, а не передавать задачи последовательно.
- Рабочий процесс требует итераций, возврата к предыдущим этапам или динамической маршрутизации, основанной на промежуточных результатах.

# Используйте инструменты для организации групповых чатов.

Модели "оркестрации групповых чатов" имитируют совместную беседу между несколькими ИИ-агентами, а также, при необходимости, с участием человека. Центральный модуль управления диалогом контролирует ход разговора, определяя, какой агент должен ответить следующим и когда запросить участие человека. Эта схема полезна для моделирования совещаний, дебатов или совместного решения проблем.

![Схема, иллюстрирующая организацию группового чата, в котором участвуют несколько агентов и ведется управляемый диалог. Центральный модуль управления чатом координирует ход обсуждения.](https://learn.microsoft.com/en-us/training/wwl-data-ai/orchestrate-semantic-kernel-multi-agent-solution/media/multi-agent-group-chat.png)

Формат группового чата хорошо подходит для ситуаций, когда групповое обсуждение или итеративное сотрудничество являются ключевыми факторами для принятия решений. Он поддерживает различные стили взаимодействия, от свободного обмена идеями до формальных рабочих процессов с четко определенными ролями и этапами утверждения. Организация групповых чатов также очень полезна в системах, где человек может направлять или вмешиваться в разговор. Обычно, в этом формате агенты не изменяют напрямую работающие системы — они в основном участвуют в обсуждении.

## Когда следует использовать систему управления групповыми чатами.

Рассмотрите возможность использования системы управления групповыми чатами в тех случаях, когда ваш сценарий включает в себя:

- Спонтанное или целенаправленное взаимодействие между агентами (и, возможно, людьми).
- Итеративные циклы "создатель-проверяющий", в которых агенты поочередно создают и проверяют результаты работы друг друга.
- Непосредственный контроль или участие человека в режиме реального времени.
- Все взаимодействия прозрачны и подлежат проверке, поскольку вся информация собирается в единой цепочке сообщений.

Наиболее распространенные сценарии включают в себя:

- Креативный мозговой штурм, в ходе которого сотрудники обмениваются идеями и развивают их друг на основе идей другого.
- Принятие решений, которое становится более эффективным благодаря обсуждению и достижению консенсуса.
- Сложные проблемы, требующие междисциплинарного диалога.
- Контроль качества и проверка достоверности, требующие учета различных экспертных точек зрения.
- Рабочие процессы создания контента с четким разделением этапов разработки и рецензирования.

## Когда следует избегать использования групповых чатов для координации действий.

Избегайте использования этой конструкции в следующих случаях:

- В большинстве случаев достаточно простого распределения задач или использования простых линейных процессов.
- Требования к скорости работы в реальном времени делают обсуждения слишком затратными по времени.
- Необходимы иерархические или детерминированные рабочие процессы, и это не подлежит обсуждению.
- Менеджер чата не может однозначно определить, когда задача завершена.
- Управление ходом разговора становится слишком сложным, особенно при большом количестве операторов (рекомендуется ограничить их число тремя или меньше для более удобного контроля).

## Циклы "разработчик-проверяющий".

Один из распространенных специальных случаев – это цикл "автор-проверяющий". В этом цикле один агент (автор) предлагает контент или решения, а другой агент (проверяющий) их рассматривает и оценивает. Проверяющий может отправлять обратную связь автору, и этот процесс повторяется до тех пор, пока результат не будет удовлетворяющим. Этот процесс требует последовательности действий, управляемой менеджером чата.

   Обрабатывайте объединенные сообщения от всех агентов. Каждое сообщение содержит имя автора и его содержание, что позволяет вам определить, какой именно агент предоставил каждый ответ.

## Настройка параметров группового чата.

Вы можете создать собственный инструмент для управления групповыми чатами, расширив базовую функциональность. `GroupChatManager` класс. Этот подход позволяет вам контролировать:

- Как результаты диалога фильтруются или обобщаются.
- Как выбирается следующий агент?
- Когда следует запрашивать ввод данных от пользователя.
- Когда следует завершить разговор.

Специализированные менеджеры позволяют реализовать логику, адаптированную к конкретным задачам и потребностям пользователя.

## Порядок действий для администратора группового чата.

В течение каждого этапа диалога менеджер чата вызывает методы в следующем порядке:

1. `should_request_user_input` - Проверяет, требуется ли ввод от пользователя перед тем, как следующий агент сможет ответить.
2. `should_terminate` - Определяет, должна ли завершиться текущая беседа (например, достигнуто максимальное количество раундов).
3. `filter_results` - В конце разговора подводит итог или обрабатывает полученную информацию.
4. `select_next_agent` - Если продолжить, выбирается следующий участник для выступления.

Это гарантирует, что ввод данных пользователем и условия завершения работы будут обработаны до продолжения разговора. Чтобы изменить поведение системы, переопределите эти методы в вашем собственном компоненте управления.

Организация групповых чатов позволяет нескольким ИИ-агентам — и, при необходимости, людям — сотрудничать посредством структурированного общения и итеративной обратной связи. Это идеально подходит для сложных задач, требующих разнообразной экспертизы и динамичного взаимодействия. Хотя это требует тщательного управления, такой подход обеспечивает прозрачность и гибкость в процессе принятия решений и творческой работы. SDK Microsoft Agent Framework позволяет легко реализовать и настроить организацию групповых чатов в соответствии с вашими потребностями.

# Используйте систему координации передачи данных.

**Организация передачи управления** позволяет ИИ-агентам передавать контроль друг другу в зависимости от контекста задачи или запросов пользователя. Каждый агент может "передать" разговор другому агенту, обладающему необходимой экспертизой, обеспечивая тем самым, что наиболее подходящий агент будет заниматься каждой частью задачи. Эта схема идеально подходит для служб поддержки клиентов, экспертных систем или любой ситуации, где требуется динамическое распределение задач.

![Схема процесса организации передачи управления (или "handover").](https://learn.microsoft.com/en-us/training/wwl-data-ai/orchestrate-semantic-kernel-multi-agent-solution/media/multi-agent-handoff.png)

Эта схема подходит для ситуаций, когда оптимальный агент неизвестен заранее, или когда требования к задаче становятся более ясными в процессе выполнения. В отличие от параллельных схем, агенты работают последовательно, передавая управление полностью от одного к другому.

## Когда следует использовать систему управления передачей задач.

В подобных ситуациях вам может быть полезно рассмотреть возможность использования паттерна "передача управления" (handoff orchestration).

- Для выполнения этих задач требуются специализированные знания или инструменты, но количество и последовательность действий, которые необходимо предпринять, невозможно определить заранее.
- Требования к экспертным знаниям возникают динамически в процессе обработки данных и определяют маршрутизацию задач на основе анализа их содержания.
- Проблемы, охватывающие несколько областей знаний, требуют последовательной работы различных специалистов.
- Вы можете определить четкие сигналы или правила, указывающие, когда агент должен передать управление и кому именно.

## Когда следует избегать автоматизации передачи задач между сотрудниками.

В некоторых случаях может быть целесообразно избегать использования паттерна "передача управления" (handoff orchestration).

- Участники процесса и их последовательность известны заранее и являются фиксированными.
- Маршрутизация задач проста и основана на правилах, не требуя динамической интерпретации.
- Неудачные решения в области маршрутизации могут вызвать недовольство у пользователей.
- Несколько операций должны выполняться одновременно.
- Избежать бесконечных перенаправлений между сотрудниками или чрезмерных "прыжков" от одного специалиста к другому – непростая задача.

## Реализация системы управления переключением (или передачи) соединения.

Шаблон "передача управления" может быть реализован в SDK фреймворка Microsoft Agent с использованием управляемых рабочих процессов. В управляемом рабочем процессе каждый агент последовательно обрабатывает задачу, и на основе результатов своей работы рабочий процесс определяет, какой следующий агент следует вызвать. Эта маршрутизация осуществляется с помощью конструкции "switch-case", которая направляет задачу к разным агентам в зависимости от результатов классификации.

1. Настройте модели данных и клиент для чата.

   - Создайте свой клиент для чата, чтобы подключаться к сервисам искусственного интеллекта.
   - Определите модели Pydantic для структурированных ответов в формате JSON, которые будут возвращать агенты искусственного интеллекта.
   - Создайте простые классы данных для передачи информации между этапами рабочего процесса.
   - Настройте агентов, предоставив им конкретные инструкции и... `response_format` Параметр для структурированного вывода в формате JSON.
2. Создайте специализированные функции-обработчики.

   - **Модуль хранения входных данных** – сохраняет поступающие данные в общую область памяти и передает их модулю классификации.
   - **Модуль преобразования данных** – преобразует ответ агента в формате JSON в структурированный объект для маршрутизации.
   - **Обработчики (executor'ы)** – отдельные обработчики для каждого возможного результата классификации, с использованием условий проверки для обеспечения корректной обработки сообщений.
3. Разработка логики маршрутизации.

   - Создайте фабричные функции, которые генерируют проверки условий для каждого значения классификации.
   - Условия проектирования для анализа входящих сообщений и возврата значения "истина" в случае получения определенных результатов классификации.
   - Используйте условия с объектами "Case" в группах граничных условий оператора "switch-case".
   - Всегда включайте ветку `Default` в качестве запасного варианта для обработки непредвиденных ситуаций.
4. Соберите схему рабочего процесса.

   - Используйте WorkflowBuilder для соединения исполнителей с помощью обычных связей.
   - Добавьте конструкцию "switch-case" для обработки групп элементов в зависимости от результатов классификации, чтобы обеспечить маршрутизацию данных.
   - Настройте рабочий процесс таким образом, чтобы он следовал первому найденному совпадению, или, если совпадение не найдено, использовал значения по умолчанию.
   - Настройте исполнение команд в терминале для получения окончательного результата.

Оркестровка передачи задач обеспечивает гибкий способ динамической маршрутизации задач между специализированными ИИ-агентами, гарантируя, что каждый этап рабочего процесса выполняется наиболее подходящим экспертом. Это особенно полезно для сложных и постоянно меняющихся задач, таких как поддержка клиентов или решение проблем в различных областях, где требования к экспертизе могут изменяться в ходе взаимодействия. Используя SDK Microsoft Agent Framework, вы можете создавать адаптивные системы, которые плавно передают управление между агентами — и при необходимости включают участие человека — для эффективного и бесперебойного выполнения задач.

# Используйте оркестровку с помощью технологии Magnetic.

**Магнетная оркестровка** – это гибкая и универсальная многоагентная модель, предназначенная для решения сложных задач, не имеющих четко заданных границ, которые требуют динамичного взаимодействия. Эта модель использует специальный "магнетный" компонент (менеджер) для координации работы группы специализированных агентов. Менеджер определяет, какой агент должен действовать следующим, основываясь на изменяющейся ситуации, прогрессе выполнения задачи и возможностях каждого агента.

![Схема потока управления с использованием магнитных технологий.](https://learn.microsoft.com/en-us/training/wwl-data-ai/orchestrate-semantic-kernel-multi-agent-solution/media/multi-agent-magnetic.png)

Менеджер Magentic поддерживает единое информационное пространство, отслеживает ход выполнения задач и адаптирует рабочий процесс в режиме реального времени. Такой подход позволяет системе разбивать сложные задачи на подзадачи, назначать их и последовательно совершенствовать решения. Процесс направлен не только на создание конечного решения, но и на разработку и документирование подхода к решению проблемы. В процессе работы создается и постоянно уточняется динамический журнал задач, в котором фиксируются цели, промежуточные цели и планы реализации.

## Когда следует использовать систему оркестровки Magentic?

Рассмотрите возможность использования паттерна "магнитная оркестровка" в следующих сценариях:

- Проблема сложная или не имеет четко определенного решения, и путь к решению заранее не известен.
- Для выработки эффективного решения необходимо учитывать информацию и отзывы от различных специалистов.
- Система должна генерировать документированный план действий для последующей проверки человеком.
- Агенты обладают инструментами, которые позволяют им напрямую взаимодействовать с внешними системами и ресурсами.
- Пошаговый план выполнения, создаваемый в динамическом режиме, повышает эффективность работы еще до начала выполнения задач.

## Когда следует избегать использования технологии "магнитного оркестрования".

Возможно, вам стоит избегать использования этой конструкции в следующих случаях:

- Путь решения является фиксированным или детерминированным.
- Не нужно составлять подробный отчет или план действий.
- Задача достаточно проста для использования более простой схемы организации процессов.
- Скорость является приоритетом, поскольку этот метод делает акцент на планировании, а не на быстром выполнении.
- Вы можете ожидать частых зависаний или бесконечных циклов без возможности найти выход из ситуации.

## Внедрение системы оркестровки Magentic.

Реализуйте паттерн "магнитного оркестрования" с использованием фреймворка Microsoft Agent.

1. Определите специализированных агентов.  
   Создайте экземпляры агентов (например, ...). `ChatAgent`...с конкретными инструкциями и клиентами, с которыми ведется общение. Каждый сотрудник должен иметь специализированную роль и набор навыков, подходящих для решения различных аспектов сложной задачи.
2. Настройте функцию обратного вызова для обработки событий.  
   Определите асинхронную функцию обратного вызова для обработки различных типов событий, возникающих в процессе оркестрации, включая сообщения от оркестратора, обновления данных, передаваемые агентом, сообщения от агента и окончательные результаты.
3. Создайте рабочий процесс в Magentic.  
   Используйте... `MagenticBuilder` Класс предназначен для создания системы управления взаимодействием. Добавьте экземпляры ваших агентов в качестве участников, настройте механизм обратного вызова событий в режиме потоковой передачи и создайте стандартный менеджер с соответствующими параметрами, такими как максимальное количество раундов и ограничения на задержки.
4. Настройте стандартный модуль управления.  
   Стандартный менеджер координирует взаимодействие между агентами с помощью клиента для обмена сообщениями, предназначенного для планирования и отслеживания хода выполнения задач. Настройте параметры, такие как максимальное количество итераций, количество простоя и количество перезагрузок, чтобы контролировать поведение системы управления.
5. Запустить процесс.
Или:
Выполнить рабочий процесс.  
   Назовите имя рабочего процесса. `run_stream` Этот метод позволяет эффективно решать сложные задачи. Он динамически планирует работу, распределяет ее между соответствующими исполнителями и координирует их взаимодействие для решения проблемы.
6. События, связанные с этапами выполнения процесса.  
   Итерируйте по событиям рабочего процесса, используя асинхронный цикл. Обрабатывайте различные типы событий, включая... `WorkflowOutputEvent`...который содержит окончательные результаты работы оркестровки.
7. Извлеките окончательный результат.  
   Соберите итоговый результат из событий рабочего процесса. Полученный результат содержит полное решение, разработанное в результате совместной работы всех участвующих компонентов системы.

Система Magentic orchestration отлично справляется с решением сложных, постоянно меняющихся задач, требующих координации в реальном времени между специализированными компонентами. Она идеально подходит для задач, где план нельзя определить заранее и который должен адаптироваться по мере поступления новой информации. Используя платформу Microsoft Agent Framework, вы можете создавать системы, которые динамически разрабатывают, уточняют и реализуют пути решения благодаря интеллектуальному взаимодействию компонентов.
